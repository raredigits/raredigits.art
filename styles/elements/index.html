css/modules/elements/

Elements are the controls a reader works with: buttons and form fields. They need no class. Inside .rd a bare <button>, <input>, <select> or <textarea> takes the library's look; outside it, a host's own controls stay as the host made them.

<input type="text" placeholder="Search the docs">
<button type="button">Search</button>
<button class="button-primary" type="button">Subscribe</button>

Three rules

Elements first, classes on top
The element has the default look; a variant, a size or a layout is a class on top of it (.button-primary, .button-sm, .form-group). .button gives a link the button look.
One height
A button and a text field of the default size are equally tall, so they line up in a row with no extra work.
Any class wins
The element defaults have type weight in every state, hover and focus included. A component that styles its own <button> (a carousel arrow, a legend toggle) overrides them with one class and never fights a :hover.

A RareCharts card (.rc-chart) draws its own controls, so the element defaults stop at it. That includes the page's own controls a chart moves into its controls row: they keep the chart's compact look.
