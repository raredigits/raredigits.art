Bricks / Cards

css/modules/bricks/_cards.scss

The card is the narrative surface: an article preview, a person, a project, a pricing block — content an author made for a reader. A panel is for data; the rule for choosing between them is on the Building Blocks page.

Card

Cards provide distinct content separation, letting you build complex hierarchies and group related elements. By default they stand out through background color, and they lay out as a flex column.

.card

A card is a versatile connector piece — it takes on any visual style through utilities: sizes, colors, margins, paddings, alignment, borders. Content-wise it can be a simple container or develop its own hierarchy, holding any content type, blocks, or interactive elements.

A card has no parts of its own: a fixed header, body and footer belong to the panel, which is for data. A card’s header is a block with .border-bottom and a padding utility, a footer one with .border-top.

.border-bottom
.border-top

Cards come in two default styles: .card and .card-inverted. Each is a surface: it paints its background from --surface-current, and a chart on it (RareCharts 0.9.8_7 and later) paints its label plates with the same colour. .card-inverted also re-maps the text, border and chart roles for its dark ground, so a panel divider or a chart on it reads (Surfaces). A .card nested in a .card-inverted is a light surface again: it takes back the page's values of those roles, a project's own on :root included.

Blocks that hang into the page margin (pre, blockquote, .lead, the caption widths) stay inside both cards, as in a panel. On paper a .card-inverted prints as a light card in a thin frame (Print).

Card Grid

When one card is not enough and the cards form a regular, repeated set, .card-grid is the special case that arranges .card-grid__item tiles into a responsive grid. It is the one place where the card surface owns its own layout, because the tiles are uniform by design. Column count defaults to five; the --cols-2 / --cols-3 / --cols-4 modifiers (or the --card-grid-cols custom property) set it; below desktop every variant collapses to two so tiles stay legible.

The card grid is for uniform, repeated tiles. For a freeform arrangement of full .card surfaces, do not reach for a component — use the grid utilities directly, as shown next.

Composing cards — no new class required

There is no .card-deck selector, and there never needs to be. A “card deck” is not a thing the library ships; it is just several cards arranged together, and arrangement is already a solved problem. Any block-level element — a <div>, a <section>, or another .card — can serve as the wrapper, and the alignment, positioning, spacing, and grid utilities do the placement.

A “deck” is just composition

This block is a .card-inverted wrapping an image, a header, prose, and a nested card — no special deck class involved.

.card.center-center.padding-lg

Cards are standard block elements capable of holding any content type: text, images, charts, tables, or interactive elements.

.card-inverted

The takeaway: any positioning a card layout needs is reachable through the existing utilities. Before adding a new class, check whether alignment and positioning already cover it — they almost always do.
