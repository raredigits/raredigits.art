## Зачем

Граф денежного следа: как ценность движется между адресами и протоколами через несколько сетей. В отличие от ego/path/cluster (прогулка по окрестности с перецентровкой), `flow` рисует **заданный подграф целиком** — результат расследования. Это не нарушает принцип «рисуем результат запроса» из [GRAPH-ARCHITECTURE](./GRAPH-ARCHITECTURE-INTERNAL.md): запрос — это сам след.

Что видно на макете и что должно получаться из чистых данных + конфига:
- **Дорожки** (lanes) — сети в порядке движения денег, слева направо, с подписями сверху.
- **Узлы** — кошелёк (круг), контракт/протокол (квадрат), биржа (ромб), толпа адресов (двойной круг); цвет по группе (свои, внешние, неизвестные, биржа, протокол, комиссия, шум); подпись + моноширинная подстрочка; пометка «end» у конечного узла.
- **Рёбра** — направленные; между одной парой бывает несколько (своп туда и обратно, депозит и вывод) — расходятся дугами. Цвет по активу, толщина по USD (корень, с клампом), пунктир для вычисленных сумм, стрелка цвета ребра, подпись.
- **Контур группы** — «один ключ в пяти сетях»: полупрозрачная обводка узлов кластера владельца с подписью.
- **Фильтры** — краудсейл, шум, подписи рёбер — снаружи (чекбоксы сайта), библиотека даёт API.
- **Ползунок времени** — рёбра, начавшиеся позже окна, и узлы без активных рёбер приглушаются (не исчезают).
- **Выбор** — клик по узлу подсвечивает его рёбра и соседей, остальное приглушено; клик по ребру — ребро и два узла; клик в пустоту снимает. Детали показывает **внешняя панель сайта**, библиотека отдаёт событие.
- **Раскрытие** — «+» на узле Juicebox открывает краудсейл (этап 2).

## Контракт данных

```js
const g = new RareCharts.Graph('#chart', {
  view: 'flow',

  lanes: [                                   // порядок = порядок слева направо
    { id: 'bostrom', label: 'Bostrom' },
    { id: 'ethereum', label: 'Ethereum', weight: 3 },   // weight: относительная ширина дорожки
  ],
  laneBy: 'lane',                            // поле узла с id дорожки (у потребителя — 'net')

  nodeGroups: {                              // цвет + подпись легенды
    church:   { color: '…', label: 'Church' },
    exchange: { color: '…', label: 'exchange' },
  },
  nodeShapes: { wallet: 'circle', contract: 'square', exchange: 'diamond', crowd: 'stack' },
  shapeBy: 'kind',                           // поле узла → ключ nodeShapes

  linkColorBy: 'asset',                      // поле ребра → linkTypes/цвет
  linkTypes: { ETH: { color: '…', label: 'ETH' }, noise: { color: '…', dash: '6 5' } },
  linkWidth: { by: 'value', scale: 'sqrt', min: 1.6, max: 22 },   // value: null → min
  linkDash: link => link.basis === 'derived',  // true → пунктир
  linkLabels: true,

  hulls: [{ id: 'owner', label: 'one key uvkv59… on five networks', members: n => n.cluster }],

  onSelect: ({ node, link, event }) => { /* внешняя панель */ },
  tooltipFormat, linkTooltipFormat,          // общий слой связей
  minWidth: 860,                             // ниже — горизонтальная прокрутка контейнера
});

g.setData({
  nodes: [
    { id: 'osmo', label: 'Osmosis main', sub: 'osmo1uvkv…w7zs', group: 'church', kind: 'wallet',
      lane: 'osmosis', row: 0, col: 0, terminal: false, /* любые поля → onSelect */ },
  ],
  links: [
    { source: 'osmo', target: 'pools', asset: 'ATOM', value: 530, label: '61.38 ATOM',
      start: '2023-09-26', end: '2023-12-27', basis: 'exact', /* любые поля */ },
  ],
});

g.setFilter(item => !item.noise);            // предикат по узлам и рёбрам; ребро скрыто, если скрыт любой конец
g.setTimeWindow(null, '2024-01');            // общий слой связей; timeWindowMode: 'dim' по умолчанию во flow
g.select('osmo') / g.select({ link: id }) / g.clearSelection();
g.setLinkLabels(false);
```

- `links` с `source`/`target` — общий словарь слоя связей; `from`/`to` принимаются как алиас (у макета и MapFlow так).
- Ребро без `id` получает стабильный id по `source→target#index`; нужен для `select` и мульти-рёбер.
- `row` — вертикальная позиция в дорожке (0 = основная линия, ±1, ±2 — выше/ниже), `col` — подколонка внутри широкой дорожки. Точные `x`/`y` (в долях 0..1 от дорожки/канваса) — ручная правка поверх.
- Время: годы, `YYYY-MM` или ISO; у ребра `start`/`end` (открытый конец = null). Сравнение унифицировано с MapFlow.
- Произвольные поля узлов и рёбер не трогаются и приходят в `onSelect`/тултипы.

## Этап 1 — 0.9.8_3 (Flows I)

**Модель.** Хранение — направленный мультиграф (graphology `directed` + `multi`), аналитика ego/path/cluster — по неориентированной простой проекции (решение шага 0, API-INVENTORY → «Flows — общий слой связей»). Это Graph A2: второе ребро пары больше не теряется, а поведение существующих видов не меняется.

**Раскладка по подсказкам.** Дорожки делят ширину по `weight`. Узел без `row` — авто-стопка внутри дорожки/подколонки в порядке входа (детерминированно, без оптимизации); с `row`/`col` — по подсказке; с `x`/`y` — точно. Узлы одной клетки разводятся по вертикали без наложения. Автоматической раскладки здесь нет — это этап 2.

**Рендер.**
- Подложки и подписи дорожек; формы узлов `circle | square | diamond | stack` + своя форма через SVG-путь; цвет по группе; подпись и `sub`; маркер `terminal`.
- Рёбра — квадратичные кривые от края до края узла; параллельные рёбра пары (в т.ч. встречные) расходятся с шагом изгиба; `bend` на ребре — ручная правка. Стрелки по цвету ребра (маркеры по ключу цвета, id уникальны на экземпляр). Хит-зона ≥ 12px. Подписи рёбер в середине кривой, с простым отталкиванием при наложении.
- Контуры групп (`hulls`) — сглаженная оболочка вокруг членов с подписью, под рёбрами, без событий.
- Легенда из `nodeGroups` + `linkTypes` + пояснение форм/пунктира/толщины; интерактивная фильтрация типов связей — как в Graph.
- Тема: цвета групп и активов — опции с дефолтами из темы; тёмная тема — через `darkTheme`/`createTheme`, без CSS-переменных потребителя.

**Взаимодействие.**
- Выбор узла/ребра → подсветка и приглушение, событие `onSelect`; Esc и клик в пустоту снимают. Hover — тултип (общий слой связей), клик по ребру пиннит тултип (Graph A3).
- Клавиатура: узлы в Tab-порядке по дорожкам; Enter/Space — выбор; стрелки — переход к соседям по рёбрам; рёбра выбираемы через соседей.
- `setFilter`, `setTimeWindow`, `setLinkLabels` перерисовывают без смены раскладки (позиции не прыгают).
- Зум/пан — существующие кнопки Graph; перецентровки по клику в `flow` нет.
- Узкий экран: контейнер с `minWidth` и горизонтальной прокруткой (как в макете). Поворот на 90° — после опыта Sankey, не в этом этапе.

**Acceptance этапа 1:** демо `/charts/graph/flow/` на данных макета (или синтетике той же формы) — 7 дорожек, ~20 узлов, ~30 рёбер, встречные пары, пунктирные рёбра, контур группы, переключатели фильтра/подписей, ползунок времени, внешняя панель по `onSelect`. Ни строчки кастомной отрисовки на стороне страницы. Тёмная тема, клавиатура, reduced motion проверены; ego/path/cluster не сломаны (тесты Graph зелёные).

**Оценка этапа 1:** ≈ 7–9 рабочих дней поверх общего слоя связей (A2/A3, `setTimeWindow`, толщина по value — считаются в общем слое релиза).

## Этап 2 — 0.9.8_4 (Flows II)

**Автораскладка внутри дорожек** — для данных из API, где координат нет:
- ранги по направлению потока (простая слоистая раскладка), с разрывом циклов (встречные свопы, возвраты) по наименьшему числу развёрнутых рёбер; порядок дорожек — ограничение;
- **основной маршрут** (самый «тяжёлый» путь по value или помеченный в данных) — на центральной линии, побочные протоколы и комиссии — выше/ниже;
- уменьшение пересечений барицентрическими проходами; детерминизм;
- `row`/`col`/`x`/`y` из этапа 1 остаются ручной правкой поверх автомата.

**Агрегация и сворачивание:**
- группа узлов (`groups: [{ id, label, members, collapsed }]` или поле узла) сворачивается в мета-узел; его рёбра суммируют `value` по паре и типу, подпись «N адресов»;
- «+»/«−» на узле-раскрывателе (как Juicebox → краудсейл в макете), `expand(id)`/`collapse(id)`, событие для синхронизации с внешними переключателями;
- агрегация параллельных рёбер пары по типу (опция), с раскрытием в тултипе/панели;
- кап на число узлов в дорожке с «+N» (как `maxNodes` в ego).

**Acceptance этапа 2:** тот же синтетический след без единой координаты в данных даёт читаемую раскладку (основной маршрут по центру, без наложений, пересечения не больше ручного варианта); сворачивание краудсейла в один узел и обратно с сохранением выбранного; тест детерминизма раскладки.

**Оценка этапа 2:** ≈ 6–8 рабочих дней (автораскладка 4–5, агрегация и сворачивание 2–3).

## Не входит (осознанно)

Свободная force-раскладка · редактирование графа · автоматическая кластеризация адресов (кластеры приходят из данных) · подгрузка соседей по клику в `flow` (это ego) · поворот на 90° на мобильных (после опыта Sankey) · экспорт в изображение.

## Тесты

- модель: мульти-рёбра пары сохраняются, направление учитывается в `flow`, ego/path/cluster не меняют поведение;
- раскладка этапа 1: подсказки соблюдаются, узлы одной клетки не пересекаются; этапа 2 — детерминизм, разрыв циклов, основной маршрут на центральной линии;
- фильтр/окно времени не меняют позиции; `onSelect` получает исходный объект узла/ребра со всеми полями;
- уникальность id маркеров/градиентов у двух экземпляров на странице;
- smoke-рендер с пустыми/частичными данными (ребро на несуществующий узел → warn + drop).
