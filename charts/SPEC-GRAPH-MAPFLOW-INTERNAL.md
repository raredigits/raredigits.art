## Часть A. Graph

### A1. Гонка `setData()` → `focus()` — багфикс (приоритет 1, дёшево)
`focus()` сразу после `setData()` нестабильно даёт пустой канвас: бутстрап memorySource асинхронный, очередь view-changes его не дожидается.
**Требование:** методы после `setData()` должны вставать в очередь за бутстрапом источника — синхронная цепочка `g.setData(d); g.focus(id)` обязана рисовать ego без ручного `whenReady()`.
**Заодно:** свериться с доком — сейчас он обещает «`setData()`: memorySource + focus», а фокус фактически ручной; после фикса решить, делает ли `setData` авто-фокус (и на кого) или док исправляется.
**Acceptance:** тест: `new Graph(el, {}); g.setData({nodes, links}); g.focus('x'); await g.whenReady()` → в SVG есть круги; повторить 20 раз без флака.

### A2. Мульти-рёбра: несколько типов связи у одной пары (приоритет 3)
Модель — простой граф: `model.js` merge → `hasEdge` → skip; второе ребро пары молча теряется. Боевой кейс: Трамп↔Кушнер = family + investment + employment; сейчас потребитель схлопывает типы на данных сам (одно ребро, приоритетный `type`, полный список в `types`).
**Требование:**
- Модель: multigraph (graphology `MultiUndirectedGraph`) либо агрегация рёбер пары с сохранением всех типов — на выбор реализации; наружу поведение одно: ни один тип не теряется.
- Вход: обратная совместимость — несколько записей links с одной парой и разными `type`; плюс принимать `types: []` на одном ребре (текущий обход потребителя) как эквивалент.
- Рендер: до 3 параллельных дуг с малым изгибом; больше трёх — одна линия + маркер «+N» (список в тултипе, см. A3).
- Легенда/`relationTypes`-фильтр: ребро (пара) видимо, если активен хотя бы один его тип; изоляция типа прячет off-type дуги пары, а не пару целиком.
**Acceptance:** демо-пара с тремя типами → три дуги; клик «family» в легенде оставляет одну дугу; `setRelationTypes(['investment'])` — аналогично.

### A3. Link-level UX: тултип и клик по ребру (приоритет 3, вместе с A2)
У рёбер есть `label` и произвольные поля, но показать их нечем — тултип только у узлов. Боевой кейс: на рёбрах лежат `sources: [{url, title}]` — посты-пруфы связи; нужно отвечать на «почему они связаны?» прямо в графе.
**Требование:** hover ребра → тултип (по умолчанию: label или список типов); опция `linkTooltipFormat: ({ link }) => html`. Ссылки внутри тултипа должны быть кликабельны — значит, тултип-«липучка»: клик по ребру пиннит тултип, клик мимо — снимает. Хит-зона ребра ≥ 8px (невидимый широкий штрих под линией).
**Acceptance:** ребро с `sources` из двух постов → пин-тултип с двумя рабочими ссылками.

### A4. Ego-раскладка: моногруппный кейс (приоритет 4)
50+ узлов одной группы вырождают секторную раскладку — всё уезжает в один сектор/угол.
**Требование:** если доминирующая группа держит >80% узлов вьюхи — fallback на концентрические кольца по глубине (без секторов), центрированные в канвасе.
**Acceptance:** 60 узлов одной группы → центрированная розетка, а не стопка в углу.

## Часть B. MapFlow — потоки на карте (новый experimental класс; приоритет 2)

**Зачем:** рисовать потоки (капитал, товары, влияние) между точками поверх карты. Первый потребитель — «Карта» раздела историй schnellreich: опиумный треугольник Индия→Китай→Лондон, евродоллар Москва→Лондон→Париж→Сингапур, золотые дау Дубай→Индия, прайс-кэп Россия→Индия→Европа. В роадмапе это давно отложенный пункт «map overlays» — реализуем как отдельный класс, не трогая стабильный Map.

### Контракт данных
```js
new RareCharts.MapFlow('#chart', {
  // геометрия — контракт Map как есть:
  topoUrl / topoData / geoUrl / geoData, topoObject, projection, fitPadding,

  nodes: [
    { id: 'GB-LON', label: 'Лондон', coords: [-0.12, 51.5] },  // точные координаты…
    { id: 'CN', label: 'Китай', country: '156' },              // …или ISO-код → центроид фичи
  ],
  flows: [
    { from: 'IN', to: 'CN', type: 'opium', value: 3,
      dateStart: 1773, dateEnd: 1860, label: 'опиум из Бенгалии' },
  ],
  linkTypes: { opium: { color: '…', dash: null, label: 'опиум' } },  // контракт Graph, переиспользовать
  timeWindow: [1839, 1860],   // null = все
  fitTo: 'features' | 'flows',
});
chart.setData({ nodes, flows });
chart.setTimeWindow(from, to);  // фильтр: пересечение [dateStart, dateEnd] с окном; null-границы = открытый интервал
```
Даты — годы (number) или ISO-строки; сравнение унифицировать.

### Рендер
- Дуги больших кругов (`d3.geoInterpolate`/`geoPath` по LineString), направление — стрелка у цели или сужение хвоста к источнику (выбрать в дизайне, одно из двух).
- Толщина = `value` через sqrt-шкалу с клампом; цвет/дэш = `type` через `linkTypes` (без типа → `t.muted`).
- Узлы: точка + label; коллизии лейблов — приоритет узлам с большей суммой value; тултипы узлов и дуг (`tooltipFormat`, `flowTooltipFormat`).
- Легенда типов — реюз legend-компонента, интерактивная фильтрация как в Graph.
- Тема/подписи/attribution — общие механизмы библиотеки; `prefers-reduced-motion` — без анимаций появления; a11y — accessible-name, `aria-label` на дугах.

### Не в v1 (осознанно)
Анимация «частиц» по дугам · UI тайм-слайдера (на стороне сайта, библиотека даёт только `setTimeWindow`) · кластеризация узлов при зуме · совмещение с choropleth-значениями Map · кривые с ручным изгибом.

### Демо и acceptance
Страница `/charts/mapflow/` с двумя демо на синтетике:
1. «Опиумный треугольник»: 3 узла, 3 потока, 2 типа — статика.
2. «Евродоллар»: узлы Москва/Лондон/Париж/Сингапур/Нью-Йорк, `setTimeWindow` переключателем 1957 / 1968 / 2025 — дуги появляются по эпохам.
Acceptance: оба демо рендерятся из чистых данных без кастомного кода кроме конфига; `setTimeWindow` меняет состав дуг без перезагрузки; resize не ломает fit.
