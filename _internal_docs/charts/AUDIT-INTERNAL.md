## Общее состояние

Библиотека развивается, но общий слой отстаёт от новых классов. Полный текущий прогон: **35 файлов / 483 теста проходят**, из них библиотека чартов — 27 файлов / 392 теста. Сборка проходит; **634 156 B min / 192 886 B gzip без баннера**, полный распространяемый JS — **635 549 / 193 870 B**. Главные дефекты — на стыках классов с `Chart`: навигация по времени, `setData`, `destroy`, выделение и форматирование. У flow есть и ошибки алгоритмов: закреплённые колонки, агрегация приглушённых связей, неоднозначные ключи корзин. Детерминированность сама по себе не означает корректность этих случаев.

Повторяется код, который уже разошёлся по поведению: экранирование HTML, легенды типов и тултипы связей; два парсера времени, два нормализатора серий, несколько обработчиков входной анимации и генераторов uid. Отсюда неверные категории/цвета, потеря стилей DualAxes и одинаковые id градиентов. Наибольшая отдача — объединять эти участки вместе с исправлением подтверждённых дефектов, сохраняя особенности каждого класса.

У старых классов — дыры жизненного цикла и входа: `setData([])` оставляет старый рисунок, новый диапазон данных оставляет старый вид, вход не сортируется, `TimeSeries` хранит строки как есть, после `destroy()` случаются поздние рендеры. Нарушены обещания: `Pie` рисует бублик, `area: false` игнорируется, навигатор не совпадает с графиком и его кисть не вызывает `onViewChange`, `darkTheme` рисует белые плашки последнего значения, без Rare Styles CSS теряет переменные хоста.

Лишний вес: `GraphModel.centrality` тянет graphology-metrics в бандл без потребителя в библиотеке, есть две неиспользуемые прямые devDependencies, CSS страниц документации во внедряемых стилях и мёртвый `niceTickValues`. Карты суммарным размером 4 610 774 B не имеют ссылок внутри репозитория; это кандидаты на исключение из поставки, но отсутствие локальных ссылок не доказывает отсутствие внешних пользователей их опубликованных URL (X-03).

Тесты зелёные, но изолированный подробный прогон `graph-ready` проходит даже с `TypeError` из d3-zoom: очередь Graph ловит и логирует исключение. Точное прежнее число «72» не используется как актуальная метрика. Есть повторяющаяся подготовка окружения и перекрывающиеся проверки, но удалять наборы целиком или добиваться заданного числа тестов нельзя: у `graph-ready`, лог-шкал и иерархий есть самостоятельные контракты.

Публичные доки (README, installation, styles/theme/settings) и внутренние планы отстают от кода. Главные решения до 1.0: состав бандла (реэкспорт d3 + стек Graph ≈ 52% gzip), единый словарь фильтров типов, формы аргументов форматтеров, дефолты анимации, разделение «тема в JS / структура в CSS» для цветов и шрифтов, распил `Graph.js`.

**1. Зафиксировать проверяемую версию и состав API.** Проверять исходники, готовый bundle и собранные страницы одного commit/version. | Что учитывать | Что проверять |

Имеющиеся инструменты имеют ограниченную область:

Зафиксировать результат и закрыть проход.** В инвентаре хранить проверенный commit/version, количество рассмотренных контрактов и незакрытые расхождения с ID задач, список выполненных примеров, воспроизводимые команды/сценарии и исключения. **Границы уверенности.** В этой итерации не выполнялись полный визуальный проход демо в браузере, проверка CDN/удалённых тегов и профилирование скорости. Указания на выпущенные релизы в §8 взяты из локальных записей проекта; это не новая проверка production. CSS-каскад, доступность, позиционирование, zoom/drag и география требуют браузерной проверки после исправления. Статическое отсутствие локального использования не доказывает, что опубликованный API/URL никому не нужен. Не выдавать legacy-бенчмарки за текущие измерения.

### Как принять уборку и подготовить релиз

1. Исправленные ID имеют конкретный коммит и проверку результата; общие причины закрываются одним пакетом. Документация и тесты описывают согласованный контракт, а не прежний обход.
2. Полный набор проходит; в Graph не остаётся необъяснённых пойманных ошибок. При объединении тестов сохранено соответствие уникальных сценариев, число тестов само по себе не критерий успеха.
3. Сборка и smoke **готового бандла** на автономной странице без Rare Styles: Line + navigator, Pie/Donut, два TimeSeries, Graph flow с folds, MapFlow, Sankey; проверены повторный `setData`, пустой ввод и destroy.
4. В реальном браузере проверены светлая/тёмная тема, узкая карточка, клавиатура, brush/zoom, короткие дуги и панели. Тесты CSS сайта не заменяют проверку автономного chart-бандла.
5. Перемерены min/gzip одной методикой, обновлены CHANGELOG, README, инвентарь и только реализованные строки бэклога. O-10 закрыт по методике §8: матрица API ↔ документация проверена в обе стороны, опубликованные примеры выполнены, ссылки/ресурсы проверены, результат и исключения записаны для конкретного commit/version. Публичные экспорты/опубликованные data-URL не удаляются под видом внутренней уборки.
6. Все три **Owner's requirements** B-07/B-01/B-03 реализованы и приняты по критериям §9; изменение их состава требует отдельного решения владельца.
7. После этого — предусмотренный проектом выпуск `v0.9.8_6`. Этот аудит сам по себе не меняет версию, не коммитит и не публикует релиз.
