# Rare Styles — Migration 0.6 → 0.7

Opened by `CSS-340` (2026-10-16). `0.7.X` is a breaking-allowed series, and **every breaking release appends its rows here**. The baseline is the public API of `v0.6.19`, the last `0.6` release, snapshotted in [`api/v0.6.19.json`](./api/v0.6.19.json): 4 017 classes, 130 `:root` custom properties, `rare.css`/`rare.min.css` plus maps, and `fonts/` and `images/`. Regenerate a snapshot with `node scripts/api-snapshot.mjs <git-ref|--working> <label>`.

Consumers stay on version pins and migrate after the release ships. Nothing here changes a pinned site until its pin is bumped. A site on the unpinned GitHub Pages URL is the exception: it takes each release when it is published, until the Pages artifact is frozen (`CSS-T00`).

## `v0.7.0` — Scope Gate & Bug Closure

### The one required step

Add `class="rd"` to the `<html>` element of every page that loads Rare Styles, in the same commit that bumps the pin to `v0.7.0`:

```html
<html lang="en" class="rd">
```

Without it the page is **unstyled**: every library rule is gated by `.rd`.

## `v0.7.2` — Charts Dependencies, Site Harvest & Consumer Requests

**Breaking.** Four class names are removed with no alias; a bare `<button>` and form fields inside `.rd` get the library look; a bare `<cite>` loses the credit look; and the reading column is one grid column wider. The steps a site has to take:

1. Replace `.card-dashboard-bordered` with `.panel .panel--bordered`, `.card-row-bordered` with `.panel__row`, and `.card-row-bordered-item` with `.panel__row-item` (rows 1–2). For a `.card-header`, use `.border-bottom` (row 54).
2. Check your buttons. They are inline-block now, the same `#fafafa` capsule with a `#333` label and a visible `#ccc` frame, 1rem in any context. Use `.button-block`, or a page rule, where a button must sit on its own line (rows 3–5).
3. Check your forms inside `.rd`. Fields, checkboxes, radios and the other inputs get the library look, and `<input type=submit|button|reset>` becomes a button (rows 6–9). Host forms outside `.rd` and controls inside `.rc-chart` are untouched.
4. A credit `<cite>` that is not a direct child of a `<blockquote>` turns inline: put a credit under an image in the figure's `<figcaption>`, or style it on your site (row 13). If you pin RareCharts older than 0.9.8_6 (0.9.8_5_1 or earlier) with this release, move to ≥ 0.9.8_6; the chart tokens take effect from 0.9.8_7 (row 26).
5. Check pages laid out against the reading measure: it is one column wider (row 31), and the caption-width blocks follow it (row 32).
6. Delete page rules that only patched v0.7.1: your own sidenote columns, row gaps, or a rule that kept the grid on tablets (rows 39–42), and your own `top` on the cookie badge (row 48).

**Rules a site may have to revisit.**
- A rule with two element selectors, such as `form button { border-color }`, now also freezes the hover and pressed frame (row 5).
- Type, weight and alignment utilities no longer act on an `a.button` (row 4).
- A `background` shorthand on a `<select>` clears the library's arrow (row 7).
- A project that re-maps `--brand-color` and uses `.button-primary` sets `--brand-color-deep` too (row 26).
- Border roles re-mapped on `:root` no longer reach inside `.card-inverted` (row 22).
- A re-mapped `-bg` twin does not change a callout: set `--callout-bg` on it (row 26).
- A `.sidenote` must be a direct child of `.sidenote-wrapper` (row 18); a table or `pre` in a note needs `.table-scroll` on a tablet (row 40).
- A margin or width utility on a `.card-caption` now wins (row 38).

**Browser floor.** The floor of `v0.7.0` holds (Chrome / Edge 111, Safari 16.4, Firefox 113). A few new rules need `:has()`, which Firefox has from 121. In Firefox 113–120 a sidenote row with a chart does not stack, a row's last block keeps its bottom margin, a banner row with a wide block puts the block under the banner, a panel with parts stays a block, and a glyph in a button stays inline; a label around a checkbox or radio keeps the default cursor, and one around a disabled control is not dimmed. The validity frames use `:user-valid` / `:user-invalid` (Chrome / Edge 119, Safari 16.5): in older browsers a field shows no green or red frame after input, while `[aria-invalid="true"]` still works. Masks are written unprefixed, which Chrome / Edge read from 120: in 111–119 the `.form-error` glyph and the `.stat--delta-*` arrows draw as filled squares, like the `rd-icon-*` glyphs since `v0.6.18`.

**Unpinned consumers.** A site that loads the old GitHub Pages URL (`raredigits.github.io/rare-styles/rare.min.css`) gets every release the moment it is published, breaking ones included. That lasts until the Pages artifact is frozen (`CSS-T00`, `v0.7.7`). Pin a jsDelivr version instead (`@v0.7.2`).
