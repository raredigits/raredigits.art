# RareCharts — Changelog

All notable changes to RareCharts are documented in this file.
Format follows [Keep a Changelog](https://keepachangelog.com/). The library follows semantic versioning.

Roadmap and planned features: [raredigits.art/charts/backlog](https://raredigits.art/charts/backlog/).

This file begins tracking at `v0.9.6`. Earlier versions were released without an itemized changelog.

> **Release checklist — the version has a single source of truth:**
> 1. Move the accumulated `[Unreleased]` entries in this file under a new `## [vX.Y.Z] — date — Title` heading.
> 2. Bump `version` in `assets/charts/src/version.json`. That value flows automatically to the runtime `RareCharts.VERSION` (`src/index.js`), the build banner (`scripts/build-charts.mjs`), and the docs version label / CDN pin (`_data/versions.js`) — nothing else to edit.
> 3. Push to `main`. CI does the rest: runs the tests, rebuilds the bundles from source (they are **not committed to git**), syncs `raredigits/rare-charts`, and pushes the `vX.Y.Z` tag — jsDelivr resolves version pins from those tags, and `@latest` only from semver tags (it stays on `v0.9.8` while releases are tagged `v0.9.8_N`). The sync only fires for a version that is not yet tagged, so pushes between releases never reach CDN consumers.
>
> Whenever the public API surface changes (new chart class, new adapter, the construction pattern), update the banner's machine-readable header in `scripts/build-charts.mjs`.

## [Unreleased]

## [v0.9.8_6] — 2026-10-26 — Flows II

The second half of the Flows release (the first, `v0.9.8_3`, brought `Sankey` and the Graph flow view). The flow view now lays out data that has no coordinates, folds a set of nodes into one with a +/− switch, merges parallel ties, caps crowded lanes and navigates time like `TimeSeries`; and a new class, **`MapFlow`**, draws flows between places over a map. Both stay **experimental** — outside the 1.0 stability guarantee.

### Added

- **Automatic layout in the Graph flow view** (`layout: 'auto'`, the default; `src/graph/layouts/flowAuto.js`, docs `/charts/graph/flow/` → Automatic layout). Nodes without `row`, `col`, `x` or `y` are placed from the ties: inside each lane a payment goes left to right; loops are broken where they would read backwards — with dates, the later tie turns (a refund, a payout years on), without dates as few ties as possible; the main route — the longest left-to-right path, the heavier by `value` on a tie, or the nodes/ties flagged `main: true` — runs along the middle; side nodes go above and below in the order that crosses fewest ties; a DEX swapped with and back, a fee or an income source stands in its counterpart's column. Deterministic. A lane without a `weight` is as wide as its columns. The docs show the demo trace with every hint removed.
- **Folds** (`folds: [{ id, label?, members, anchor?, collapsed?, sub?, group? }]`, `src/graph/views/flowFold.js`). A set of nodes collapses into one node at the anchor's place: a **−** switch on the anchor while open, **+** on the folded node, the + and − keys on a focused node, `aria-expanded`. The folded node's ties sum `value` per pair and category; ties inside disappear; its caption is `sub` (`'{n} addresses'` or `n => …`), its colour the fold's `group` (the anchor's by default), its tooltip lists the members. The selection follows a member into the fold and back to the anchor. Methods `collapse(id)`, `expand(id)`, `isCollapsed(id)`, `setFolds(list)`; event `onFoldChange({ id, collapsed, fold, event })`.
- **`aggregateLinks: true`** — parallel ties of one pair and category drawn as one, `value` summed, the originals listed in the tooltip and kept in `link.links`.
- **`laneCap: n`** — a lane with more than `n` nodes shows `n`: its `n − 1` heaviest and a "+N more" node holding the rest (fold id `lane:<lane>`), opened with its +.
- **Time navigation in the flow view** — `timeframes` (preset keys or `{ key, label, range }`) and `navigator`, as on `TimeSeries`, over the ties' `start`/`end`. The navigator strip, with a time axis, shows how many ties are active per day, month or year (a tie without an `end` counts as still running, as `setTimeWindow` reads it); brush it to pick a period. Ties outside it dim. With navigation on, `setTimeWindow()` moves the view and the buttons follow; `setTimeframe`, `setView`, `getView` and `onViewChange` work as on `TimeSeries`.
- **`RareCharts.MapFlow`** (experimental; `src/charts/MapFlow.js`, docs `/charts/map/flow/`). Built on `Map` — same geometry options, projections, zoom and theme — with the `{ nodes, links }` contract of `Graph` and `Sankey`. A node stands at `coords: [lon, lat]` or at the centroid of its `country`'s largest polygon. Each flow is a great-circle arc that bows to one side (A → B and B → A never overlap; parallel flows fan out), width by `value` (square-root scale, `linkWidth`), colour and dash by `type` (`linkTypes`), an arrowhead at the target. A legend of types turns them on and off (`hiddenLinkTypes`, `linkLegend`, `setLinkTypesVisible()`); `setTimeWindow(from, to)` hides (or dims, `timeWindowMode: 'dim'`) flows outside the window and fades places left without any; `fitTo: 'links'` frames the places and their arcs instead of the whole map. Place labels give way to each other, heavier places first. Hover tooltips; click or Enter pins a flow's tooltip. A time scale like `TimeSeries` has: `timeframes` (era buttons with `{ key, label, range }`) and a `navigator` strip with a time axis showing how many flows run over time — brush it to pick a period; `setTimeWindow()` then moves the view. Two demos: the opium triangle, and dollars outside America on a time scale (1957 / 1968 / 2025 / All).
- **`Overview` takes `margin` and `axis`** — the navigators of the flow view and `MapFlow` span the drawing (no Y-axis gutter) and show a time axis under the strip; `TimeSeries` is unchanged.
- **`barWidth`** (`Bar`, `DualAxes`; `src/core/barLayout.js`) — a bar width in px. On `Bar`: the width of a vertical bar, the thickness of a horizontal one, the whole column of a stacked bar. On `DualAxes`: the width of each bar, with `series.barWidth` for one series (series, then chart, then `barWidthRatio`); a cluster is the sum of its bars, centred on the date. With categories the bar stays centred in its slot (in date mode and on `DualAxes` the scale is inset by half a bar, see Changed); a width larger than the space per category or date is cut to it (a cluster narrows in proportion), so neighbours touch but never overlap. Anything that is not a positive number is ignored; an explicit width drops the 2px floor and 48px cap of Bar's ratio. Docs: Bar → Bar width and color, with a demo; Stacked Bar, Dual Axes and Combined tables.
- **Per-bar colour on `Bar`** — a row's `color` fills its bar (`{ label, value, color }`, `{ date, value, color }`), then `barColor`, then the theme accent; `''` counts as no colour. `setData` repaints a bar whose colour changed or went away, and hover only dims it. Stacked bars ignore a value's `color`: segments keep their series colour.
- **Annotations on the dated `Bar`** (`annotations`, `annotationLabelHeight`; docs `/charts/bar/` → Annotations, with a demo). A vertical `Bar` fed `{ date, value }` rows takes the markers of `Line` — points and ranges on dates, lines and bands on values — over the bars, on the chart's own scales. They follow timeframes, the navigator and `setView`, move with new data, take negative values, and clear with an empty window or `setData([])`; the pointer passes through them to the bars' tooltips. Labels get room above the plot as on `Line` (an explicit `margin.top` wins). A range between two bars' dates spans the bar centres — start and end it half a period out to shade whole bars — and levels do not widen the value axis (a level beyond it is not shown). Categorical, stacked and horizontal bars have no date axis: they draw nothing and warn once per chart.
- **`theme.tooltip.header`** (`{ text, bg }`, both `null` by default) colours the row that names what is hovered: the date in Line, DualAxes and TimeSeries, the label in Bar, HierarchicalBar and Donut, the title in Map, MapFlow, Sankey and Graph. `null` keeps today's look (a date muted, a title bold); `bg` draws the header as a band across the top of the tooltip. A Donut slice label keeps its slice colour.
- **`createTheme(overrides, base)`** — an optional second argument, the theme to merge onto: `createTheme({ tooltip: { bg: '#000000' } }, RareCharts.darkTheme)` keeps the rest of the dark tooltip.
- **Tooltip row classes** (`rare-charts.css`): `.rc-tooltip-header`, `-title`, `-muted`, `-sub`, `-kind`, `-value`. The built-in tooltips are made of them, and a `tooltipFormat` can use them to match the default look and follow `theme.tooltip`; the `tooltipFormat` and `linkTooltipFormat` contracts are unchanged.
- **`whenReady()` on every chart** — a promise that resolves with the chart once it has drawn what it loads: Graph its requests and layout, `Map` and `MapFlow` their geometry (also when the geometry fails to load; the error is logged). The other charts draw on `setData()`, so theirs resolves at once. Only Graph had it. A `Map` given no geometry source now warns in the console instead of staying silent.
- **`window.RareChartsConfig = { injectStyles: false }`** for a strict Content Security Policy: set before the bundle, it stops the injected `<style>`, and the page serves `rare-charts.css` as a file (Installation → Strict Content Security Policy). Each release now publishes `rare-charts.css` next to the bundle in `rare-charts`, so a pinned CDN copy is available. A `<link id="rc-base-styles">` stops the injection too.
- **`graticule: true` on `Map`** draws a 10° grid of meridians and parallels under the regions, in `theme.map.graticule`. Off by default; not drawn with `projection: 'identity'`.

### Changed

- **Nodes without hints in the flow view are laid out automatically** instead of stacking in input order in column 0. Any position hint pins a node as before, so fully hinted traces — the docs demo, the data project's — look the same; `layout: 'hints'` brings back the stage-1 placement.
- **The flow demo** folds the crowdfunding side with the library's fold instead of page code switching a filter, takes `start`/`end` from each tie's period, and navigates time with three chapter buttons and the navigator.
- **Chart subtitles wrap** (all chart types; `rare-charts.css` → `.rc-chart-subtitle`) instead of being cut with an ellipsis; the title stays on one line. A long subtitle makes the header taller and the plot area that much shorter within the same `height`. Its line height is `1.2em`, so a wrapped subtitle stays compact.
- **The legend has no padding of its own** (`.rc-legend`): it lines up with the title and the plot instead of sitting inset.
- **Timeframe buttons sit flush right on charts without a Y-axis gutter** (`Map`, `MapFlow`, the Graph flow view: `.rc-chart-range-row--flush`); line charts keep the 60px above their axis labels.
- **Chart text takes the chart font throughout** (`rare-charts.css`): the flow view's node sub-lines and tie labels (were monospace), the navigator's time axis (d3's `sans-serif` default removed), and the page's own details panel — its headings no longer take the site's heading font.
- **The flow view's navigator spans the drawing**: with the details panel beside it, the strip stops where the panel begins; a few px inside the card's edges keep the brush handles visible, and an axis label that would run past either end is dropped instead of cut. The strip spans the ties' dates exactly (it used to stop at the start of the last month, so the selection's right handle fell off the edge); `Overview.setBrush()` clamps to the strip.
- **Last-value labels sit 7px further left** (`Line`, `DualAxes`; `renderEndLabels` places them 3px past the plot instead of 10px): values longer than four or five characters (`$88.4K`, `1,234.56`) no longer run into the card's edge. The label may cover the last few px of its line.
- **Docs: `note` and `controls` are named wherever a chart page points to the common options**, and the composed header-and-footer example on Settings now carries a `note`; Circular and Graph pages got the pointer they lacked.
- **`Map`** keeps its projection after rendering and fits it to `_fitObject()` — internal hooks for `MapFlow`; its public API and output are unchanged.

- **Categories of ties resolve one way in every relation chart** (`core/links.js` → `resolveLinkType`). Visible changes: in the flow view a tie without a category is now muted (it took the first palette colour) and is labelled "connection"; on ego/path/cluster views a type `linkTypes` does not describe takes a free palette colour (it was muted). Sankey keeps undescribed types muted, since its legend lists described types only.
- **MapFlow `tooltipFormat` is for places only**; a country under the flows takes `regionTooltipFormat` (Map's `{ feature, item }` payload).
- **The navigator lines up with the plot**: its side margins follow the chart's own (they were a fixed 0 / 70 px); `navigator: { margin }` is merged side by side.
- **The library no longer loads fonts** (`rare-charts.css`). The injected stylesheet dropped its `@import` of Google Fonts, so a page with RareCharts makes no request to fonts.googleapis.com / fonts.gstatic.com (on raredigits.art those faces used to replace the self-hosted Fira Sans and Cousine on every chart page, page text included). Charts use Fira Sans and Cousine when the page provides them — Rare Styles self-hosts both — and a system stack otherwise (`system-ui … sans-serif`, `ui-monospace … monospace`; `theme.font` and `theme.numericFont` fall back the same way). For the old look on a page without these fonts, add the `<link>` from Installation → Fonts and Rare Styles; for other fonts, set `--rc-font-family` / `--rc-font-family-numeric` with a selector that outranks `.rc-chart` (the library's stylesheet is injected last), such as `:root .rc-chart`. Semi-bold text is bold now, since no host ships a 600: the Graph breadcrumb, the "+N more" panel title, the map tooltip title.
- **The chart font reaches every part of the card**: `font-family` is set once, on `.rc-chart`. Without Rare Styles the subtitle, legend, source and note took the page's font, and the Graph zoom/full-screen buttons the browser's button font; the Graph tool buttons and the timeframe buttons now take `font: inherit` (the timeframe buttons keep a 1.15 line-height). Nothing changes on Rare Styles pages.
- **Missing values in `Line`, `DualAxes` and `TimeSeries` leave a join, not a dip to zero**: a `null`, `''`, boolean or non-numeric value is dropped (it was drawn as 0, `true` as 1), in `TimeSeries.setData` and `appendPoint` too. That covers blank CSV cells from `fromCsv`; a DualAxes bar series skips the date instead of drawing a zero bar. A dashed DualAxes series appears without the draw-in, as a dashed Line series already did.
- **Last-value plates on the light theme take the page background** (`theme.bg`: `--bg-color` under Rare Styles, white otherwise) instead of always white, so on a grey page they no longer show as white chips.
- **The map ocean is transparent by default** in both built-in themes (`theme.map.ocean` was `var(--bg-color)`): the page shows through, as the Map docs always said; under `darkTheme` it is no longer the page's light colour.
- **MultiChart's default `gap` is 32px everywhere** — it was 16px on pages without Rare Styles.
- **`rare-charts.min.js` embeds its stylesheet minified** (comments and whitespace removed, same rules); `rare-charts.js` keeps `rare-charts.css` as written.
- **Ids in a chart's `<defs>` have one per-chart format** (`rc-<salt>-<n>-clip`, `…-ts-grad`, `…-arrow-0`). None was documented; the gradients keep `rc-ts-grad` / `rc-ov-grad` as classes to style them by.
- **Graph's model no longer bundles graphology-metrics**: its unused internal `centrality()` and `link()` are gone, and the Graph page no longer says the model computes betweenness — node importance is degree (`sizeBy: 'degree'`).
- **Docs: per-series options.** The Line, Dual Axes and Combined tables list `strokeDash` and `markers`, `markerShape`, `markerSize`, `markerFill`, `markerStroke` per series; every `markerShape` row names all five shapes (`triangle` and `cross` were missing).
- **DualAxes with bars insets its time scale by half the widest bar or cluster** (C-27): the first and last bars are drawn whole, lines start and end at the bar centres (about 5.5px per side on "Index and yearly change", 12px on the LTCM combined demo), and `xPad` is the gap from the plot edge to the outer edge of the edge bars. Annotation ranges and levels still reach the plot's edges, so a range can shade an edge bar whole. A chart without bars is unchanged. Bar's date mode is inset the same way, so its bars move inward by half a bar — up to 24px with the default ratio.
- **`barWidthRatio` on DualAxes is a share of the smallest gap between bar dates** — it was the gap between the first two dates of any series, lines included. Regular data looks the same. Bars now follow their own dates: irregular dates get narrower bars that no longer overlap, and bars under a denser line series (monthly bars over a daily line) get wider ones — they were sized to the line's step.
- **The crosshair reads the plot padding as the nearest end of the view** (`Line`, `DualAxes`): an edge bar shows its tooltip across its whole width, and hovering Line's 8px `xPad` gutter shows the edge point.
- **Tooltip typography lives in CSS; colours come from the theme as custom properties.** Size (13px), weights and spacing are in `rare-charts.css`; `theme.tooltip` reaches it as `--rc-tooltip-*` properties set on the tooltip, and only data colours (series, slices, link categories) stay inline. A page rule that outranks `.rc-tooltip`, such as `.rc-chart .rc-tooltip { font-size: 14px }`, now restyles the tooltip, colours included — before, the inline styles always won.
- **Every secondary tooltip row reads `theme.tooltip.muted`** (dates, percentages, counts, periods, shares — the stacked Bar's share of the total, a plain row before, is now muted like Donut's); they read the chart's `theme.muted`, and `tooltip.muted` was read nowhere. Its light default moved from `#888888` to `#666666`, the chart's own muted, so the default look is unchanged. A page that set `theme.muted` to recolour its tooltips should set `theme.tooltip.muted`.
- **TimeSeries tooltip date** is 13px with no gap under it, as in Line and DualAxes (it was 14px from `theme.fontSize`, with a 4px gap); the date format is unchanged.
- **Relation-chart tooltips share one tie layout**: the MapFlow flow tooltip takes Graph's (the category above its label, value and period); the Graph node's group and per-type counts read as categories, as in the flow view; tooltips cap at 280px (Graph nodes were 260px, ties 300px); "+N more" is 11px.
- **Links in tooltips** (a tie's `sources`) take the tooltip's text colour, underlined, while hovering as well as when pinned — they were the browser's blue, unreadable on a dark tooltip.
- **`theme.fontSize` is not used** (its last reader was the TimeSeries date) and goes at 1.0. Of the theme's fonts only `numericFont` is read, as the tooltip font family, with `font` as its fallback.
- **Docs**: the Dual Axes `margin` row gave the right margin as 92; it is 64 on both sides. The MultiChart page no longer says a panel can be "any other type".
- **Default number labels on Line and Bar.** Linear value-axis ticks are labelled by their step: grouped numbers below 1,000, SI prefixes from 1,000 (one prefix for the whole axis), zero as `0` — `145 150 155 160` instead of `150 150 160 160`, `0 0.5 1` instead of `0.0 500m 1.0`, `0 0.5M 1M` instead of `0.0 500k 1.0M`. Line end labels and tooltip values take three significant digits (`147`, `−0.6`, `1.23k`), so `−0.6` no longer reads `−600m`. Bar's vertical, horizontal, dated and stacked axes follow the same rule. An explicit `yTickFormat` / `xTickFormat` wins; percent (`+.2%`, `.0%`) and log (`.3~s`) labels are unchanged.
- **TimeSeries picks its default date format from the span in view**: `%H:%M` up to 36 hours (a tick at midnight names the day), `%b %d` up to 92 days (at most one tick a day), `%b` up to a year, `%b '%y` up to five years, `%Y` beyond. The 1M view read "Sep Oct Oct Oct" and the ALL view had no year. Bar's date axis, which repeated months the same way under its `'%b'` default, follows the same rule. An explicit `xTickFormat` wins.
- **Horizontal Bar value labels fade in at their places** while the bars grow, instead of appearing at the bar base and jumping to the bar end.
- **A partial `margin` fills the sides it leaves out with 0**, not the base chart's 8/70/16/0. With `margin: { top: 10 }`, `Map`, `MapFlow`, `Graph` and `MultiChart` got a 70px gutter on the right; a map now spans the card and its timeframe buttons stay flush right. Axis charts work out the sides they need, as before; `Donut`, `Pie`, `Gauge`, `Sankey` and `Graph` fill the card and do not use `margin` (Settings says so).
- **The header follows the card, not the window** (`rare-charts.css`). `.rc-chart` is a size container, and the header stacks — buttons under the subtitle — on a card 460px wide or narrower, whatever the window. It used to stack on windows up to 768px, whatever the card: a narrow card on a desktop now stacks, and a 461–768px card on a tablet keeps its buttons beside the title. A chart inside a box that shrinks to its content (an inline-block, a flex-row item) needs a width.
- **Crowded date labels thin out on every time axis** (`Line`, `DualAxes`, `Bar` with dates): the overlap check halves the tick count it asks of d3, not the labels drawn — a time scale may answer six with twelve quarter ticks, so the labels used to stay crowded. Bar's date axis now uses the same shared axis.
- **The plot keeps at least 80px.** When the title, subtitle, buttons, legend and footer wrap on a narrow card and would leave the plot less, the card grows past `height` by the difference and returns to `height` once they fit. The plot used to shrink to nothing. A height the page set on the card is left alone.
- **HierarchicalBar label layout.** From a plot 480px wide a row reads name → bar → value: names in a column of up to 40% of the width, flush against the bars (a long name wraps once, then ends in an ellipsis; `labelAlign: 'left'` lines the names up at the left edge, indented by depth), bars from one zero line shared by every row, values in a right-aligned column. Narrower, the name keeps its line above the bar and is shortened to the width, so long names no longer run past a phone-width card. Stacked, depth indents the name only, not the bar; parent rows are semibold; a gap sets each branch group apart. The default `rowHeight` is 28 side by side and 44 stacked, so chart heights change. The portfolio demo drops its root row (the total is in the title) and its `labelMaxLength`.
- **MultiChart rebuilds a panel at the breakpoint.** The narrow layout depends on the container width alone (`0 < width ≤ mobileBreakpoint`); a grid with `columns` ≤ `mobileColumns` used `mobileOptions` on any screen. Crossing the breakpoint used to patch a panel's options, so `height` and `margin` from `mobileOptions` applied only in part — the plot was resized but not moved, and the card kept its height. Each panel with `mobileOptions` is now built again with the options of the new side and its last data: `mc.charts[i]` is a new instance, state set through the panel's own methods starts over, and with `animate` on its entry plays again.
- **Map hover lightens a region's own fill**: it moves `theme.map.hoverBrighten − 1` of the way towards white (1.3, so 30%; 1.2 in the dark theme; 1 turns it off) — black lightens too, nothing turns pure white, and a fill already very light darkens a little instead. Every region with data used to hover to `matchFill` mixed 16% toward white, whatever its own colour. `hoverFill` still wins.
- **Graph flow view keyboard**: nodes share one Tab stop instead of one each, and the ties have their own stop, before the nodes. A stop is the selected item, else the one focused last. ↓ / ↑ continue into the next / previous lane, so every node can be reached; Home / End go to the first / last node or tie.

- **`RareCharts.d3` is a documented subset of the bundled D3**, not the whole namespace: `format`, `formatPrefix`, `timeFormat`, `timeParse`, `utcFormat`, `utcParse`; `sum`, `min`, `max`, `extent`, `mean`, `range`; `scaleLinear`, `scaleTime`, `scaleLog`, `scaleOrdinal`; `color`, `rgb`, `hsl`, `interpolate`; `timeDay`, `timeWeek`, `timeMonth`, `timeYear`, `utcDay`, `utcWeek`, `utcMonth`, `utcYear` — every function the docs and examples use. The minified bundle is about 47 KB smaller gzipped. **Breaking** for a page that took anything else from `RareCharts.d3` (selections, shapes, geo): load D3 itself (README, Installation). (K-13)
- **One rule for formatter arguments**, backward compatible: the formatters of Line, DualAxes, TimeSeries, Bar, HierarchicalBar, Donut/Pie, Gauge and Map get the role fields `label`, `value`, `date`, `color`, `percent`, `series` (whichever apply) — on the object they already receive, or, where the first argument is a number, a data row or a tree node, as the next argument (Gauge `centerText`: the fourth). The relation charts keep their own payloads (Sankey's `valueFormat` takes only the number). Settings → Formatter arguments has the rule and a per-class table. (K-09)
- **`Overview` is a documented public class** (Time Series → Overview, standalone navigator) and reads dates as the charts do — a Date, an ISO string or epoch ms, in the rows, `extent` and `setBrush()`; string dates used to draw nothing. (K-04)
- **Donut `drillTo(child)`** is documented next to `drillUp()` and `drillToDepth()`: it takes a child of the level shown — the page's own object, its `id` or its `label` — and draws what a click draws; **`generateMockPrices()`** stays exported as a demo helper outside the stability guarantee. (K-21, K-04)
- **Relation data is read in one place** (`normalizeRelationData` in `core/links.js`): Graph (every view and its model), MapFlow and Sankey keep their own rule for ends that name no node (Graph creates the node, MapFlow drops the link with a warning, Sankey drops it when `nodes` is given and derives the node otherwise), and Graph's model no longer reads its links twice. Link ids keep their format, now frozen for 1.0: a link's own `id` wins; otherwise `source→target#n` (MapFlow, Sankey, the flow view) and `source→target|type` (Graph's ego/path/cluster views, one tie per pair and type across loads). The `flows` alias works in every Graph view and in `memorySource`. (K-07)
- **`Graph.js` is split** the way the flow view was: the ego/path/cluster drawing (`graph/views/network.js`), the card chrome (`graph/chrome.js`) and the default tooltip and details HTML (`graph/tooltips.js`); `Graph.js` keeps the options, the source queue, view switching and the public API (2,199 → 955 lines). No behaviour change. (D-11)

### Deprecated

- **`viewSteps`**, the old name of `timeframes`: it still works (`timeframes` wins when both are set) and warns once per chart; removal is planned for v0.9.9. (K-04)

### Removed

- **The rest of the D3 namespace from `RareCharts.d3`** (see Changed). (K-13)
- **`theme.service`** — undocumented; its only use was the plate behind last-value labels, now `theme.bg`. A theme that set `service` should set `bg`.
- **Docs-page CSS no longer ships in the library**: `.rc-demo-*` (the Visual options controls) and `.price-chart-*` (the TimeSeries page's price header and stats) moved to the site's stylesheet; the unused `.rc-demo-btn*` rules and the dead aliases `.range-btn` and `.price-chart-range-bar` are gone (the library has emitted `.rc-range-btn` / `.rc-chart-range-bar` since March). A page that styled its own markup with these classes needs its own CSS.
- **Four unused map files** (4,610,774 bytes): `data/maps/countries.json`, `data/maps/world/level-0/world-atlas/countries-10m.json` and `data/maps/world/level-0/disputed/visionscarto-world-atlas/{110m,50m}.json`. No page or example used them, and neither the README nor the docs offered them. They leave `raredigits.art/assets/charts/data/` and `rare-charts` from this release on; earlier tags keep serving them, and the same files are published upstream (`cdn.jsdelivr.net/npm/world-atlas@2/countries-10m.json`, `cdn.jsdelivr.net/npm/visionscarto-world-atlas@1/world/110m.json`, `50m.json`). The kept `countries-110m.json` and `countries-50m.json` now ship with world-atlas's ISC notice beside them.

### Fixed

Found by a library-wide audit before the release; the fixes come with regression tests, each checked to fail without its fix.

- **Input** — `parseDate` no longer lets an Invalid Date, `NaN`, `null` or `false` through (Line used to crash on them, or plot 1970). Time series are drawn in date order whatever order they arrive in. `TimeSeries.setData` parses ISO-string dates and copies its input; `appendPoint` no longer changes the caller's array. Categorical `Bar` rows take string labels and numeric values (a numeric label with `labelMaxLength` used to throw; CSV strings compared as text); a row without a value keeps its category on the axis without a bar. The adapters parse a mapped date and coerce a mapped value, whether the mapping is a key or a function; an empty value is kept.
- **Empty data** — `setData([])`, or a window with nothing in it, clears the drawing (it used to stay), on Line, DualAxes, TimeSeries, Bar, Donut and the Graph flow view.
- **Time navigation** — the view after `setData`: a selected timeframe re-applies to the new data, a window the data no longer reaches falls back to the full range (it used to invert). An explicit window outside the data stays an empty window. `defaultTimeframe` accepts a custom `{ key, range }` step. On relation charts (Graph flow, MapFlow) view bounds read like the ties' own: `defaultView: [1990, 2000]` is two years, not two milliseconds; years 0–99 are no longer 1900–1999.
- **Navigator** — a drag now reports through `onViewChange` when it ends (also when it is brought back to zero width); a click on the strip no longer erases the brush; `area: false` works; the strip lines up with the plot on Line, Bar and DualAxes and spans every series, so dates only a later series covers can be brushed to. The TimeSeries wheel and drag zoom start from the window on screen (after a timeframe or a brush, the first wheel step used to jump towards the whole range) and clear the timeframe selection.
- **Tooltips** — the default tooltips escape data (a label like `<img onerror=…>` from a CSV used to run); a user `tooltipFormat` is still HTML. The TimeSeries tooltip sits at its point instead of a header's height above it. Hovering an emptied chart no longer shows the old data.
- **Relation charts** — a tie's category resolves one way everywhere: the flow tooltip names the `linkColorBy` category the drawing shows (it used to say "connection"), arrowheads of Cyrillic categories no longer share one colour, and an undescribed type takes a palette colour that no described type uses (see Changed). In the flow view the selection follows a node into its fold and a tie into its merged tie, and `onSelect` hears when it moves or goes; `select()` of a folded member selects its fold; the details panel describes a fold; a fold whose anchor is hidden keeps its − switch; in dim mode a merged tie counts only the ties in the window. Automatic layout keeps a pinned `col` (what follows lands to its right) and leaves the widths of a fully hinted trace alone. Ids that contain `→` or `|` no longer merge different pairs; numeric node ids work as their strings. A Graph source's late answer no longer reaches data that replaced it. MapFlow: `tooltipFormat` is for places, countries take `regionTooltipFormat` (a place formatter used to throw on country hover); a very short arc no longer points backwards; Enter pins the tooltip at the arc; `fitTo: 'links'` with every place at one point falls back to the map; the default tooltip lists `sources`. A Sankey `setData` with a cycle keeps the previous data instead of failing on every resize.
- **destroy()** — stops late renders (font load, map fetch, queued graph work, a full-screen frame); undoes only the library's own classes and inline sizes on the container; hands the page's `controls` element and a page-owned Graph `details` panel back to their place; releases a pinned map tooltip; leaves full screen.
- **Series styles** (`Line`, `DualAxes`) — per-series `strokeDash` works on DualAxes (the series was drawn solid), and per-series `markers`, `markerShape`, `markerSize`, `markerFill`, `markerStroke` work on both (only the chart-level marker options took effect, so the Combined docs example drew neither its dash nor its markers); `markers: false` on a series hides its markers under a chart-level `markers: true`. `strokeWidth: null` or `''` draws the default 2px line instead of an invisible one; a `null` series or row no longer throws. Both charts build their series with one normaliser that passes every field of a series through.
- **Two charts on one page** no longer share gradients, clip paths or arrowheads. The area gradients of `TimeSeries` and of every navigator had fixed ids, so the second chart painted its area with the first one's colour, or with nothing when the first was hidden — with this release's navigators on Line, Bar and DualAxes, any two charts with a navigator. Every id in a chart's `<defs>` now comes from a per-chart prefix, and every navigator strip — built in or a standalone `Overview` — has its own.
- **Themes** — the plate behind a last-value label was white in every theme (each value sat on a white chip under `darkTheme`); it is `theme.bg`. The navigator's tints over the strip and inside the window were hard-coded black; they are `theme.text` at the old strengths, so the light theme looks the same.
- **Charts on pages without Rare Styles** — the CSS and the theme read Rare Styles variables without fallbacks: legend dots and bands were 0×0, header, legend, footer and tooltip spacing collapsed, timeframe buttons lost border and padding, annotation plates and inside bar labels turned black, halos vanished, the map ocean went black, the source line ignored its margin and ellipsis, and the title was the browser's 13px `h5`. The CSS now has its own spacing tokens on `.rc-chart` (`--rc-space-xs/sm/md/lg` = 4/8/16/32px, the Rare Styles scale, so the site does not move), every host variable it reads has a fallback, `theme.bg` is `var(--bg-color, #ffffff)`, the source is a block and the title takes `--rc-font-size`.
- **`RareCharts.Pie` draws a pie.** It was `Donut` under another name, so `new Pie()` drew a ring with a centre total; it now defaults to `innerRadius: 0` — and with it the pie's `padAngle`, `cornerRadius` and no centre text. Every other Donut option and method works as before, and an explicit `innerRadius` still makes a hole.
- **Docs: the map snippets load a file that exists** — the Map (Geographic data, Minimal example) and Map Flows snippets pointed at `/assets/charts/data/countries-110m.json`, gone since `v0.9.1_1`; they now use `/assets/charts/data/maps/world/level-0/world-atlas/countries-110m.json`, the file the demos load.
- **Edge bars** — DualAxes cut its first and last bars in half at its clip; with `barGrouping: 'cluster'` the outer series' bars at both ends were missing, and a timeframe window cut the bar at its end (raising `xPad` did not help). Bar's date mode had no clip at all: its edge bars ran off the left of the chart and under the value labels on the right. Both now inset the scale (see Changed).
- **DualAxes bars on irregular dates** — Jan 1, Mar 1, Mar 2 and May 1 gave 210px bars that covered each other; the width now comes from the smallest gap between bar dates. Bar colour and `barOpacity` were set only when a bar was first drawn, so a new series `color` from `setData` never showed; a Bar `barColor` changed through MultiChart `mobileOptions` now repaints too.
- **Tooltips** — `theme.tooltip.muted` takes effect; a dark tooltip on a light chart no longer shows its secondary rows in the chart's grey and Graph neighbour names in black. A dark tooltip with partial overrides can now be built with `createTheme(overrides, darkTheme)` (spreading `{ ...darkTheme, tooltip: { … } }` still merges onto the light defaults), and the tooltip's size can be overridden from the page with a selector that outranks `.rc-tooltip`, such as `.rc-chart .rc-tooltip` — the inline 13px used to win over any rule. A long name in a Graph, flow or MapFlow tooltip wraps inside the box instead of running past its edge.
- **Horizontal annotations stay inside the plot** (`Line`, `DualAxes`, `TimeSeries`, `Bar`) — a level outside the visible value range is skipped, and a band is cut at the plot's edge with only its real edges drawn; they used to run into the label room above the plot or over the X axis (`TimeSeries`, whose axis hugs the data, was hit hardest). The rule replaces the log-scale filters, so a band from at or below zero on a log axis no longer draws a false edge along the bottom.
- **MultiChart says when a chart `type` is unknown** — `RareCharts.MultiChart: charts[1] has an unknown type "Donut" — drawn as Line. Supported types: 'Line', 'Bar'.` (a wrong case gets `Did you mean 'Bar'?`). The cell still draws a `Line`, and no `type` still means `Line` without a warning; a `type` that names an `Object.prototype` member (`'constructor'`, `'toString'`, `'__proto__'`) no longer throws.
- **Docs** — Styles: `surface` is Graph node fills and flow lane bands, not tooltip panels, and the Typography table says what `font`, `fontSize` and `numericFont` do; Circular: the tooltip example uses the muted class instead of a hard-coded `#888`.
- **`source` parts without `href`** — a `{ text }` part renders its text; it printed `[object Object]`.
- **A timeframe step without a `key`** (`{ label, range }`) lights its button when chosen, by a click or `setTimeframe(label)`.
- **`navigator: 0` and `navigator: ''` no longer draw the strip** — only `true` or an options object turns it on.
- **TimeSeries keeps its view across `setData` and `appendPoint`**, as every other time chart does since T-03. A selected timeframe re-applies to the new data and moves with an appended point, its button staying lit. A window the data still meets stays where it was. Before, `setData` dropped back to the default view, and `appendPoint` kept the old window — with a timeframe selected (ALL included) the new point fell outside the view and the button went dark.
- **TimeSeries honours `crosshair: false`** — the crosshair lines and the tooltip stay off.
- **TimeSeries widens the value range to linear `yTickValues`**, as Line does. Ticks outside the data were drawn off the plot.
- **An explicit `margin.top` wins on TimeSeries and DualAxes**, as on Line and Bar — with annotations both raised it to `annotationLabelHeight + 4`, and DualAxes to 30px with an axis title. Without `margin.top` nothing changes.
- **Line with `yAxisPosition: 'left'` keeps a 64px right gutter while end labels are on.** The last-value labels were cut at the card's edge. With `endLabels: false` the right margin stays 0.
- **Date ticks on short spans** (`Line`, `DualAxes`) — with the default `'%m/%d'` format a span of a few days read "01/01 01/01 01/01 01/02…"; the axis now puts one label on each midnight in view, and a span inside one day gets one label at its start.
- **Area fills stay inside the plot** (`areaBaseline`, Line and DualAxes). `'zero'` under data that never reaches 0 ends at the bottom of the plot, instead of running over the X axis and the source line. A numeric baseline beyond the value range stops at the nearer edge.
- **Theme sizing tokens are the fallbacks they were documented as** — Line, DualAxes and the crosshair ignored them. `theme.strokeWidth` (2) sets a series without its own `strokeWidth`, `theme.markerSize` (4) the markers when neither the series nor the chart sets `markerSize`, `theme.barOpacity` (0.35) DualAxes bars without the `barOpacity` option, and `theme.dotRadius` (3) the crosshair dots. The defaults are the old values, so default charts look the same.
- **Bar's timeframe buttons and navigator appear only with a date axis** — categorical rows, stacked series and `orientation: 'horizontal'` drew the buttons, which did nothing (`getView()` stayed `null`), and an empty navigator strip that took the plot's height. They are hidden now and come back when the same chart gets dated rows; a header that held only the buttons hides with them.
- **`yPrefix` / `ySuffix` on every vertical `Bar`** — only categorical bars applied them; the date-based mode and stacked bars ignored them. A `'percent'` axis keeps its own unit, and an explicit `yTickFormat` still wins.
- **`Bar` says when dated rows meet `orientation: 'horizontal'`** — such rows have no date axis and were drawn as unlabelled bars without a word; the chart now warns once that they need `'vertical'`.
- **`HierarchicalBar`'s tooltip share is of the total** — it was the share of the longest row, so with `showRoot: false` the largest child read 100% (Equities, 60 of 100), and in a forest the largest root did. The total is the root's value, shown or not, or the sum of a forest's roots.
- **The first and last x-axis labels stay inside the chart.** A label is centred on its tick, so one on a tick a few px from the plot's edge ran past the svg and was cut off — TimeSeries at 1M, whose first weekly tick can sit on the left edge at a 0px margin. Line, TimeSeries, DualAxes and dated Bar now shift an edge label back inside, and hide it if that would run it into its neighbour.
- **The Lin/Log button keeps one width.** "Log" is wider than "Lin" in a proportional font, so the button, pinned right, changed size and moved its left edge on every switch. It is now as wide as the wider of its two labels, custom `labels` included.
- **A host rule cannot reshape the card header.** A page rule that puts every element of a block in grid columns (Rare Styles' `.sidenote-wrapper :not(:first-child, .sidenote)` spans each over five) opened empty columns in the header grid, gaps and all, and cut the title of a chart in a sidenote to an ellipsis. The header places its parts at a specificity such rules do not reach.
- **Donut drill-down** — the slice you click to drill in now leaves the ring. It used to stay under the new one: its colour showed in the gaps, and hovering a gap showed its tooltip. A slice that comes straight back (drill in, then up at once) stays live, and with `animate: false` the previous level goes at once. Drilled in, the whole hole is the button back up (only the text glyphs were), reachable with Tab and pressed with Enter or Space; a pie goes back up through its breadcrumb.
- **Map** — `tooltipFormat` gets `item: null` for a region without data, as documented. It was `undefined` for every feature with an id, so an `item === null` check failed. MapFlow's `regionTooltipFormat` gets `null` too.
- **MapFlow** — a place's label keeps off other places' dots; it could cover a close neighbour, e.g. London over Brussels and Amsterdam. A legend button pressed with Enter or Space keeps focus; focus used to fall to the page, so the next key did nothing.
- **Graph `onNodeClick: null` turns node clicks off**, as documented — `null` was read as the default and every click still recentred; `false` does the same.
- **Graph tie width reads `weight` before its legacy alias `strength`**, as the ego layout, the tooltip and the model already did (a tie carrying both was drawn by `strength`). The cluster view keeps its widths: its community ties now carry the width as `weight` (0–1, full at eight edges) and the number of edges between the two communities as `count` — a `linkTooltipFormat` there sees `link.weight` from 0 to 1 instead of the edge count.
- **The Graph details panel counts a tie listed both ways once** in the ego, path and cluster views, as the drawing and the tooltip do (A→B and B→A of one type said "Connections 2" and listed both); the flow view keeps both directions.
- **Flow view `nodeShapes`** — the map is read first; a kind that it does not list and that is not a built-in shape draws a circle. A kind starting with m or M (`mixer`, `Multisig`) used to be drawn as an SVG path of its own name, so the node was invisible.
- **Flow view `timeWindowMode: 'hide'` fades nodes left without a tie in the window**, as dim mode and `MapFlow` do — they stayed at full strength with no ties.
- **Flow view `minWidth` scrolls only the drawing**: the svg sits in a `div.rc-graph-scroll` that scrolls sideways, and the title, buttons, legend, navigator, details panel and footer stay in place. The whole card used to scroll, taking the header and the navigator's brush off screen on a phone.
- **Keyboard in Graph** — Escape or × on the hidden-nodes list gives focus back to "+N more" (it fell to the page); a legend button in the ego and flow views keeps focus after Enter or Space redraws the legend, so the next key works.
- **Entry animations play through the renders that follow `setData`.** `document.fonts.ready` and the first `ResizeObserver` callback both render right after it: Bar, HierarchicalBar and the Sankey band fade were cut to their end state there, so in a browser the motion was never seen, and Line, DualAxes, Donut and Gauge restarted or re-timed their entry. The entry now runs on one timeline per chart (`core/entryMotion.js`): a render in the middle of it — those two, a resize, new data — carries each mark on from where it stands to the new geometry, on the rest of the same easing curve. What animates when is unchanged: once per chart for Line, DualAxes, Bar, Gauge and a flat Donut; each drill for Donut; each `setData` for HierarchicalBar and Sankey. A bars-only DualAxes no longer ends a resize on stale bar heights.
- **All charts.**
  - `onViewChange`, `onScaleChange` and a standalone `Overview`'s `onBrush` stay quiet after `destroy()` — also for a navigator drag that ends after it, a button the page still holds, or a late `setView()` / `setYScale()`.
  - When several timeframes cover the same window (`YTD`, `1Y` and `ALL` on this year's data) and none was chosen, `ALL` (or `MAX`) lights, not the first of them in the list; a brush or `setView()` back to the whole range no longer lights `2Y`. A step that was clicked or set with `setTimeframe()`, or `defaultTimeframe` while its view holds, stays lit.
  - Navigator drags render once per animation frame, the latest window winning; the end of the drag applies at once and reports through `onViewChange`. Relation charts work out their ties' extent and strip series once per dataset, not on every render. On a 3,000-point Line a 120-move drag renders 54 times instead of 121.
  - `legendPosition: 'right'` with a navigator keeps the page's `controls` between the navigator and the source line; they dropped below it.
  - A page's `button:hover` background (Rare Styles has one) no longer fills the timeframe buttons, and the Lin/Log button keeps its diagonal fill when hovered on the linear scale.
- **Bar and DualAxes.**
  - Horizontal Bar value labels are placed on each render's own scale; a transition end or a timer from an earlier render no longer moves them to stale places after a resize.
  - Horizontal Bar measures its category gutter: it was a fixed 65px, so long labels ran off the card at any width. It now grows to the longest label (after `labelMaxLength`), from 65px up to 40% of the chart width; a longer label is cut with an ellipsis and keeps its full text in the tooltip. Stacked horizontal bars do the same; an explicit `margin.left` keeps the gutter as given.
  - DualAxes `y1Ticks` / `y2Ticks` reach the auto domain, which was always rounded to 4 intervals: `y1Ticks: 10` on 12…87 gives 10…90, not 0…100.
- **Donut, Gauge and trees.**
  - Donut: every `setData` repaints the ring — a new `color` for a slice that stays was ignored, and a palette colour now follows its slice's position, as the tooltip and legend already had it. Slices that share a label without an `id` keep their own paths, matched in order, instead of being dropped and drawn again on every render; an `id` keeps a slice when the order changes.
  - Donut legend items without a `color` take the colour of the slice with the same `id` or `label`; they were painted by position, so items listed in another order than the data, or next to a zero value the ring left out, took a neighbour's colour. Band and dashed marks are repainted too. An item whose slice is not in the ring (a zero value, a level drilled away from) keeps the accent; an explicit `color` is kept.
  - A tree node with no `value` of its own whose children are all undisclosed got 0: the Donut drill-down drew an empty slice and could show `NaN%`, and HierarchicalBar printed `0`. It is now undisclosed — "not disclosed" in the Donut, `?` in HierarchicalBar — and left out of every sum.
  - Gauge `setData({ value, max, min })` overrides `max` / `min` for that call only; the override stuck to every later `setData`.
- **Map and MapFlow.**
  - An arc across the edge of the map no longer draws a straight line across it, and `'orthographic'` no longer shows arcs and places from the far side of the globe. Each arc is the great circle as `d3.geoPath` cuts it: across the antimeridian it leaves at one edge and comes back at the other, each part bowed on its own; on the globe only the near side is drawn — a place behind it has no dot or label, a flow toward it runs to the horizon without an arrowhead, and a flow between two hidden places is not drawn and not in the Tab order.
  - With `zoom`, dots, labels and arrowheads keep their size on screen; they grew with the zoom, up to 12×, while the arcs kept their width. Labels are placed again as you zoom, so crowded places get theirs when there is room.
  - `fitTo: 'links'` keeps the arcs in the frame: it fitted only the places, so a long great circle (China → New York over the Arctic) or an arc's bow could leave the map. Every flow counts, so the time window and the legend do not move the frame.
  - The theme tokens `map.hoverBrighten` and `map.graticule` take effect (see Added and Changed); neither was read.
- **Graph.**
  - `setData()` in the ego, path and cluster views starts over: the breadcrumbs and `back()` begin with the new data's first view, the legend lists only its relation types, and `overview()` returns to a centre of the new data. The default centre is the node with the most distinct neighbours over the ties the view draws (under `relationTypes`, ties of those types); ties to themselves and ties without both ends no longer count. An empty payload clears the drawing, legend and notes instead of leaving the previous data on screen.
  - `connect(a, a)` draws that node once, instead of three identical routes from it: `memorySource` answers `[[a]]`, and the path view drops repeated routes.
  - Path view: labels at the left and right ends stay inside the drawing ("Verdant Group" was cut at 1280px).
  - Details panel (`details: true`): a node's ties show only their → / ← marker, not a bullet as well, on pages without Rare Styles too.
  - Flow view: a drawing too short for its rows gives up its top and bottom padding before captions touch the node below — in a 900px card with title, buttons, legend and navigator, rows went from 58 to 74px apart. Drawings with room are unchanged.
  - Keyboard: ego, path and cluster nodes and flow ties can be reached and used from the keyboard, with a visible focus and an accessible name. Focus shows the tooltip; Enter or Space acts as a click; Escape clears.

Covered by `test/hierarchical-charts.test.js`; documented at [`/charts/bar/hierarchical-bar/`](https://raredigits.art/charts/bar/hierarchical-bar/). Removed from the [backlog](https://raredigits.art/charts/backlog/).
- **Donut drill-down (hierarchy mode)** (`src/charts/Donut.js`). Passing a single root object instead of a flat array turns the donut into an interactive drill-down over the same tree contract: it opens on the root's children, clicking a slice with children descends, the center (or a breadcrumb) goes back up — `drillTo()` / `drillUp()` / `drillToDepth()` are public. Breadcrumbs appear only once drilled in, flush with the chart's left edge; the center readout follows the focused node; a surfaced remainder draws as a muted slice; named-but-undisclosed children (`value: null`) are counted in a "N not disclosed" note rather than drawn. The flat array path is untouched. Documented in the Drill-down section of [`/charts/circular/`](https://raredigits.art/charts/circular/).
- **Shared tree normalizer** (`src/core/hierarchy.js`). One contract for every hierarchy consumer (and the future spatial `Hierarchies`): authored nodes `{ label, value?, color?, children?, remainderLabel? }` with a tri-state `value` — a number `> 0` is disclosed, an explicit `null` is kept as a *missing* placeholder excluded from every sum, anything else drops the leaf. A parent's stated value is authoritative and may exceed the sum of its children; the difference is a genuine remainder, surfaced as a synthetic child only via a node's `remainderLabel` or the chart-level `showRemainder: true` — never silently. Children exceeding the stated value flag `overflow` and warn (or throw under `strict: true`). Identity is assigned in a second top-down phase, so duplicate sibling subtrees and a real node colliding with a synthetic remainder still get distinct ids. 25 tests in `test/hierarchy.test.js`.
- **Gauge: speedometer needle and any-sweep geometry** (`src/charts/Gauge.js`). `needle: true` draws a pointer pivoting on a hub at the dial center, animated to the value together with the fill; the center readout moves below the hub, dial-style; `needleColor` overrides the theme text color. Works with any `startAngle`/`endAngle` sweep — the half-circle automotive look is `±Math.PI / 2`. Documented in the Speedometer section of [`/charts/circular/`](https://raredigits.art/charts/circular/).
- **Donut/Pie outer labels: collision handling** (`src/charts/Donut.js`). Leader-line labels now resolve overlaps: per side, rows are spread apart to a minimum gap (small adjacent slices no longer overprint), each label truncates with an ellipsis to the room between its anchor and the chart edge (the full text stays in the tooltip), and the center readout fits the hole — the value shrinks its font down to a floor instead of poking out, the secondary line truncates. Covered by `test/circular-fit.test.js`.

### Fixed

- **`Bar` entry animation raced the layout and froze bars short** (`src/charts/Bar.js`). When the first render landed while the header was still settling (fonts loading, flex layout), bars animated toward a stale plot height and stuck at a fraction of it — re-renders were swallowed by the once-per-instance guard, which was only set on transition end (an event that never fires for an interrupted transition). The guard is now set synchronously and re-renders `interrupt()` the in-flight tween and finalize to the current scale. Applied to all three bar geometries (categorical vertical/horizontal and time-series).
- **Gauge center label clipped on shallow arcs** (`src/charts/Gauge.js`). For sweeps ending near ±90° the circle center sits at the drawing's bottom edge, and the label below it fell outside the svg. The radius/centering math now reserves room for whatever hangs below the circle center — the arc's own bottom or the text block — so nothing clips; deep arcs (the ±135° default) keep their previous geometry to within a pixel.

### Changed

- **SVG text styling moved from inline attributes to the stylesheet** (`rare-charts.css`, all chart classes). Chart code no longer sets `font-family`/`font-size` per element (~60 inline `.style()` calls removed); the svg inherits the small text size, `.rc-axis` / `.rc-axis-cat` classes give value and category axes their numeric/regular families (overriding d3-axis's own `font-size="10"`/`font-family="sans-serif"` group attributes), and numeric text (bar values, donut percents, center totals) is covered by per-class rules. Computed sizes (donut/gauge center) and behavioral styles (cursor, opacity, pointer-events) stay in JS. No visual change.
- **Docs: chart cards host the chart element itself.** Example containers across the bar, stacked, hierarchical, and circular pages moved the card classes onto the chart div (the pattern the standalone examples already used), so axis and outer labels breathe into the card padding instead of clipping at the svg edge. The drill-down example lives in its own `examples/pie-and-donut/donut-drilldown.js`.
- **Build banner lists the new class** (`scripts/build-charts.mjs`). `HierarchicalBar` added to the machine-readable Types list.

## [v0.9.8_1] — 2026-07-12 — Graph Rework (experimental)

The experimental `Graph` relaunched: from a single force simulation to a headless graph model with three deterministic views, relation-type filtering, and semantic navigation. Graph remains **experimental** — outside the 1.0 semver guarantee. Also ships a categorical `Bar` fix and the release automation that were waiting under Unreleased.

### Added

- **Graph rework — headless model, deterministic views** (`src/charts/Graph.js`, `src/graph/`). `Graph` is now a viewport over a headless `GraphModel` (graphology) that accumulates everything the user walks, fed through a source-adapter contract (`neighbors` / `paths` / `aggregates`; `memorySource()` simulates a backend over a static payload — swap in a real adapter without touching the class). Three deterministic views replace the force simulation: **ego** (grid rings by degree of separation, category corners), **path** (layered "how are A and B connected" routes with endpoint context and the shortest route called out), and **cluster** (Louvain communities as meta-nodes) — with semantic zoom between ego and cluster, hand-draggable nodes, and identity-preserving recenter transitions. Covered by `test/graph.test.js` (37 tests: model, layouts, source adapter, and the viewport interaction contract). Documented at [`/charts/graph/`](https://raredigits.art/charts/graph/).
- **Graph navigation and filtering** (`src/charts/Graph.js`, `rare-charts.css`). Relation-type filtering over the ego view — a `relationTypes` option, `setRelationTypes()` / `clearRelationTypes()`, and an interactive legend (click isolates a type, Shift/Ctrl/Cmd-click multi-selects, "Show all" resets); the filter drives both the traversal and what is drawn, and untyped links act as a single `default` type. Breadcrumb history with `back()` restores prior ego/path/cluster states together with their filter. The `+N more` capacity note is now an actionable disclosure listing the capped-out nodes — click one to refocus on it. Removed from the [backlog](https://raredigits.art/charts/backlog/).
- **Graph progressive data contract.** Nodes need only an `id`, links only `{ source, target }`: labels fall back to ids everywhere (canvas, tooltip, breadcrumbs), endpoint nodes are auto-created, link type and weight default sensibly — every view renders from a links-only payload, pinned by contract tests. Removed from the [backlog](https://raredigits.art/charts/backlog/).

### Fixed

- **Categorical `Bar` now renders negative values** (`src/charts/Bar.js`). The vertical and horizontal category modes hard-coded a `[0, max]` scale domain, so a negative bar computed a negative height/width — an invalid rect that silently didn't render (the time-series mode already handled negatives). The domain now always includes 0 and extends to the data on both sides; bars grow from the zero baseline in both directions, entry animation starts at the baseline, and horizontal value labels flip to the correct side of a negative bar. Covered by `test/bar-negatives.test.js`.

### Changed

- **A GitHub Release is published automatically on release** (`.github/workflows/sync-charts.yml`). The sync already pushed the `vX.Y.Z` tag (which drives jsDelivr); now it also creates the human-facing card on the `rare-charts` Releases page, lifting the title and notes from this changelog's entry — so the Releases page no longer lags the tags.

## [v0.9.8] — 2026-07-03 — Axes & Accessibility

The pre-freeze groundwork release. Two axes features close out the backlog's Axes section: hiding an axis now reclaims the margin it occupied — so a flush or sparkline look no longer needs a manual `margin` override — and `TimeSeries` gains the visibility toggles every other cartesian class already had. Around the code: the library's first automated test suite (122 tests, now gating every deploy and CDN sync), accessibility groundwork (`prefers-reduced-motion`, accessible names on every chart), a release pipeline where the CDN only ever receives tagged versions, a documentation catch-up for every working option, and an MIT license consistency fix — plus a real adapter bug the new tests caught.

### Added

- **Hiding an axis now reclaims its margin** (`src/charts/Line.js`, `Bar.js`, `DualAxes.js`, `TimeSeries.js`). Turning an axis off (`showXAxis` / `showYAxis` / `showY1Axis` / `showY2Axis: false`) previously only dropped its ticks and labels — the default margin the axis occupied stayed behind, so a flush or sparkline look required a manual `margin` override. The default margins now track what actually occupies each gutter: a hidden axis collapses its side to `0`, and where a gutter is shared the space is kept while any occupant remains — `Line`/`DualAxes` keep the right margin while `endLabels` are on, `DualAxes` keeps an axis gutter while its `y1Title`/`y2Title` is set. An explicit `margin` always wins. Covered by `test/axes-margins.test.js`; removed from the [backlog](https://raredigits.art/charts/backlog/).
- **Axis-visibility toggles on `RareCharts.TimeSeries`** (`src/charts/TimeSeries.js`). The `showGrid` / `showXAxis` / `showYAxis` options that `Line`, `Bar`, and `DualAxes` already expose now work on `TimeSeries` too — previously its grid and both axes rendered unconditionally. Hidden axes reclaim their margins, same as above. Removed from the [backlog](https://raredigits.art/charts/backlog/).
- **Test harness — Vitest + jsdom** (`vitest.config.js`, `test/`). First automated tests for the library (122 across 10 files, including the axes tests above). Pure-function coverage of `core/utils.js` (date parsing, timeframe extents, stroke-dash, marker paths, nice ticks, annotation normalization, motion gating), `core/seriesPath.js` (line/area/band geometry, baseline), `core/theme.js` (theme merge), `applySvgA11y`, and the `fromArray` adapter — plus render **smoke tests** that construct every chart type (`Line`, `Bar`, `Donut`, `Gauge`, `DualAxes`, `TimeSeries`, `Map` via inline GeoJSON, `MultiChart` with children), feed data, and assert a labelled `<svg>` renders without throwing, including edge data (empty/all-zero Donut, Gauge value parsing and clamping). jsdom layout/`ResizeObserver` shimmed in `test/setup.js`. Run with `npm test` (watch) or `npm run test:run`. Tests live in repo-root `test/`, outside the Eleventy-published `assets/charts/`.
- **Reduced-motion support** (`src/core/utils.js` → `prefersReducedMotion()` / `motionDuration()`, `rare-charts.css`). Honours the OS `prefers-reduced-motion: reduce` setting: a CSS media query neutralizes in-chart CSS transitions, and `motionDuration()` collapses D3 animation durations to 0 so transitions resolve instantly. Applied to every animating chart type — `Bar`, `Line`, `DualAxes`, `Donut`, `Gauge` (`TimeSeries`, `Map`, `MultiChart` have no entry animation; `Graph` is experimental and excluded from 1.0).
- **Accessible name on the chart SVG** (`src/core/renderHelpers.js` → `applySvgA11y()`). The root `<svg>` now carries `role="img"` and an `aria-label` derived from `title`/`subtitle` (or an explicit `ariaLabel` option), so screen readers announce the chart instead of skipping it. Applied to `Bar`, `Line`, `TimeSeries`, `DualAxes`, `Donut`, `Gauge`, `Map` (`MultiChart` delegates to its child charts; `Graph` is experimental and excluded from 1.0).

### Fixed

- **`fromArray` / data adapters kept rows with a non-finite `value`** (`src/adapters/index.js`). The filter `!row.value || isFinite(row.value)` let `NaN` through because `NaN` is falsy (`!NaN === true`), so a row whose value failed to parse (e.g. `+'x'`) was not dropped despite the documented intent. Now uses `row.value == null || Number.isFinite(+row.value)` — an absent value and a legitimate `0` are kept, a present-but-non-finite value is dropped. Surfaced by the new test suite.

### Changed

- **Single source of truth for the version** (`assets/charts/src/version.json`, `scripts/build-charts.mjs`, `_data/versions.js`). The version was stamped by hand in four places — `index.js`, the triplicated build banner across three `package.json` esbuild scripts, and `_data/versions.json` — which could (and did, per the old release checklist) drift. Now `version.json` is the only place to edit: the runtime `RareCharts.VERSION`, the build banner, and the docs label all read from it. The build moved from inline `esbuild` CLI calls to a small Node script (`scripts/build-charts.mjs`) that composes the banner once and emits both bundles; `_data/versions.json` became `_data/versions.js`. No change to the public API or bundle output.
- **License field corrected to MIT** (`package.json`). Was `ISC`, contradicting the `LICENSE` file and README which both state MIT.
- **Documentation catch-up for existing options** (source header comments; docs pages). Every working option is now listed both in its class's header comment — the reference a human or LLM reads next to the code — and in the docs tables. Newly documented: `defaultView` (all date-based charts), `xTicks` on Line, `animate` on MultiChart, `reflectY` and `projection: 'identity'` on Map, `labelContent` and the actual pie-mode defaults on Donut, the global `strokeDash`/`markers` group and `yAxisPosition` on Line, the area/marker group on DualAxes, `areaColor` and tick formatters on TimeSeries. The Map `topoObject` doc no longer claims it is required (the code falls back to the topology's first object).
- **Built bundles removed from git** (`.gitignore`). `rare-charts.js` / `rare-charts.min.js` are build artifacts: every consumer — the site deploy, the CDN sync, local dev — rebuilds them from `src/` via `npm run charts:build`, so the committed copies could only drift from the source (and had). The source of truth in git is `src/`; ready-made bundles are distributed from the `raredigits/rare-charts` repo as before. No change to the published files.
- **Tests gate CI** (`.github/workflows/deploy.yml`, `sync-charts.yml`). `npm run test:run` now runs before the site build and before the CDN sync — a failing test blocks both.

## [v0.9.7] — 2026-06-19 — Footnotes

Finishes the chart footer. Two new attribution slots — an editorial `note` and a linkable, multi-part `source` — so the interpretive line and the data credits live inside the component instead of as hand-built markup glued around it. Plus a set of edge-rendering fixes (axis titles, web-font timing, flush bar labels) that surfaced while wiring a real client chart.

### Added

- **`source` accepts links and multi-part attribution** (`src/core/Chart.js` → `_renderAttribution`, `rare-charts.css`). Beyond a plain string, `source` now takes `{ text, href }` (a single linked attribution) or an **array of parts** — strings render as plain text, `{ text, href }` objects as links — so a footer can mix several linked and unlinked sources on one line (e.g. `Source: NASDAQ, Bloomberg, Internal calculations` with the first two linked). Links inherit the source text color (set apart by an underline, so they adapt to light/dark theme), open in a new tab with `rel="noopener noreferrer"`, and an array source wraps instead of truncating so every attribution stays visible. String and `HTMLElement` sources are unchanged. Flows through `MultiChart`'s shared footer. Removed from the [backlog](https://raredigits.art/charts/backlog/).
- **`note` text slot on every chart** (`src/core/Chart.js`, `rare-charts.css`). A new footer option renders a `<p class="rc-chart-note">` below the source line in `theme.muted`, for disclaimers, data caveats, and editorial context. Accepts a string or an `HTMLElement`. This was the recurring anti-pattern the settings page warned about — interpretive captions hand-built as a stray `<div>` glued under the chart container — now an in-component slot the chart owns. Long notes wrap (including unbroken tokens like URLs, via `overflow-wrap`) and the plot shrinks to keep the note inside the card rather than overflowing it. Also flows through `MultiChart`'s shared footer. Documented at [`/charts/settings/`](https://raredigits.art/charts/settings/); removed from the [backlog](https://raredigits.art/charts/backlog/).
- **Machine-readable bundle header + `RareCharts.VERSION`** (`src/index.js`, build banner in `package.json`). The minified bundle is opaque to anyone — human or LLM — handed only the file. The header now states the global, the `new RareCharts.<Type>(selector, options).setData(data)` construction pattern, the full list of chart classes, the container requirement, that d3/CSS are bundled, and that external data loads via the `fromJson`/`fromCsv`/`fromApi`/`fromArray` adapters — so consumers stop guessing class names or hardcoding structure. `VERSION` is also exported as a runtime constant for build identification. Pairs with the text-slot conventions added to [`/charts/settings/`](https://raredigits.art/charts/settings/).

### Changed

- **Axis titles clip to their margin instead of running off the chart** (`src/core/renderHelpers.js` → `renderAxisTitles`, `src/charts/DualAxes.js`, `src/core/utils.js` → `warnAxisTitleClipped`). `y1Title` / `y2Title` are now measured by rendered pixel width against the available axis margin (its exact overflow-clip boundary) and trimmed with an ellipsis only when they would actually be cut off — narrow glyphs in a terse title like `N · K HLX`, and the uppercase transform applied via CSS, are accounted for as they render, so a label that fits (e.g. `Inflows`) is left intact. The full text is kept as a hover `<title>`, a one-time console hint fires, and `axisTitleMaxLength` caps the length explicitly.

### Fixed

- **Horizontal bar value-axis end labels no longer clip at the chart edge** (`src/charts/Bar.js`). When the value axis sits flush against the card (`margin.left` / `right` = 0), the centered first/last tick label (e.g. `0`) was half-cut by the card's overflow clip. The first label is now anchored `start` and the last `end`, so both sit fully inside the plot while the bars stay flush.
- **Text-dependent layout now settles after the web font loads** (`src/core/Chart.js`). First paint can happen before the bundled font (Fira Sans) finishes loading, so measurements taken against the wider fallback font were wrong — axis titles that fit were trimmed, X-axis labels over-thinned, end-label boxes mis-sized. Each chart now re-renders once on `document.fonts.ready`, so these measurements are correct without waiting for a resize. The re-render does not replay entry animations.

## [v0.9.6] — 2026-06-14 — Confidence Bands

Adds a band (confidence-ribbon) primitive to `Line` and the supporting legend and tooltip work to make it readable. Targeted at forecasts and any figure where a single line would overstate precision. Also corrects two `strokeDash` defects that were documented but didn't work.

### Added

- **`band` series type on `RareCharts.Line`** (`src/charts/Line.js`, `src/core/seriesPath.js`). A series marked `type: 'band'` with `{ date, lower, upper }` points renders a filled ribbon between the two boundaries at each x — for confidence intervals (P10–P90 cones), min/max envelopes, and error bands. The band draws behind every line and area, both bounds participate in the Y scale, and it mixes freely with ordinary line series in the same `setData` call. Fill uses the series `color` at `fillOpacity` (default `0.16`). Detected by `type: 'band'` or by the presence of `lower`/`upper` on the first point. Documented at [`/charts/line/band/`](https://raredigits.art/charts/line/band/) with two examples (`examples/line/line-chart-band.js`, `examples/line/line-chart-forecast.js`).
- **Band readout on hover** (`src/core/Crosshair.js`). A band reports its range in the crosshair tooltip as `lower – upper` (e.g. `P10–P90: $1.95M – $3.65M`). It draws no crosshair dot — a band has two edges and no single point, so a dot would be ambiguous; markers and end labels skip it for the same reason.
- **Legend swatch types** (`src/core/Chart.js`, `rare-charts.css`). A legend entry's `type` now selects its swatch so the legend matches the on-screen encoding: `'band'` → filled square, `'dashed'` (or `dash: true`) → dashed rule, `'dot'` / `'bar'` → dot (unchanged), default → solid rule. Needed because a forecast draws actuals, P50, and the range in a single hue, where the legend has to carry the distinction.

### Changed

- **The crosshair only reports a series where its data covers the cursor date** (`src/core/Crosshair.js`). A partial series — a forecast band or a projected line that starts part-way along the axis — no longer snaps its nearest endpoint across the whole width; it stays silent outside its own date range. When nothing is under the cursor, the crosshair line, dots, and tooltip clear. **This affects every chart that uses the crosshair, not only bands** — in practice it only changes charts whose series span different date ranges.

### Fixed

- **Per-series `strokeDash` was documented but never applied.** The field was listed in the Line options table and read during render, but `_normalizeData` dropped it, so a per-series dash pattern had no effect. It is now carried through and works.
- **`resolveStrokeDash` rejected raw dash-array strings** (`src/core/utils.js`). The options table implied a value like `'4,3'` was accepted, but only the named presets (`'dashed'`, `'dotted'`, `'dashDot'`, `'longDash'`) resolved — any raw string fell through to `null`. A numeric dash-array string (e.g. `'5,4'`, `'4 3'`) is now passed through as-is.
