RareCharts Changelog

RareCharts — Changelog

All notable changes to RareCharts are documented in this file. Format follows Keep a Changelog. The library follows semantic versioning.

Roadmap and planned features: raredigits.art/charts/backlog.

This file begins tracking at v0.9.6. Earlier versions were released without an itemized changelog.

Release checklist — the version has a single source of truth:

  1. Move the accumulated [Unreleased] entries in this file under a new ## [vX.Y.Z] — date — Title heading.
  2. Bump version in assets/charts/src/version.json. That value flows automatically to the runtime RareCharts.VERSION (src/index.js), the build banner (scripts/build-charts.mjs), and the docs version label / CDN pin (_data/versions.js) — nothing else to edit.
  3. Push to main. CI does the rest: runs the tests, rebuilds the bundles from source (they are not committed to git), syncs raredigits/rare-charts, and pushes the vX.Y.Z tag — jsDelivr resolves version pins from those tags, and @latest only from semver tags (it stays on v0.9.8 while releases are tagged v0.9.8_N). The sync only fires for a version that is not yet tagged, so pushes between releases never reach CDN consumers.

Whenever the public API surface changes (new chart class, new adapter, the construction pattern), update the banner's machine-readable header in scripts/build-charts.mjs.

[Unreleased]

[v0.9.8_6] — 2026-10-26 — Flows II

The second half of the Flows release (the first, v0.9.8_3, brought Sankey and the Graph flow view). The flow view now lays out data that has no coordinates, folds a set of nodes into one with a +/− switch, merges parallel ties, caps crowded lanes and navigates time like TimeSeries; and a new class, MapFlow, draws flows between places over a map. Both stay experimental — outside the 1.0 stability guarantee.

Added

  • Automatic layout in the Graph flow view (layout: 'auto', the default; src/graph/layouts/flowAuto.js, docs /charts/graph/flow/ → Automatic layout). Nodes without row, col, x or y are placed from the ties: inside each lane a payment goes left to right; loops are broken where they would read backwards — with dates, the later tie turns (a refund, a payout years on), without dates as few ties as possible; the main route — the longest left-to-right path, the heavier by value on a tie, or the nodes/ties flagged main: true — runs along the middle; side nodes go above and below in the order that crosses fewest ties; a DEX swapped with and back, a fee or an income source stands in its counterpart's column. Deterministic. A lane without a weight is as wide as its columns. The docs show the demo trace with every hint removed.
  • Folds (folds: [{ id, label?, members, anchor?, collapsed?, sub?, group? }], src/graph/views/flowFold.js). A set of nodes collapses into one node at the anchor's place: a − switch on the anchor while open, + on the folded node, the + and − keys on a focused node, aria-expanded. The folded node's ties sum value per pair and category; ties inside disappear; its caption is sub ('{n} addresses' or n => …), its colour the fold's group (the anchor's by default), its tooltip lists the members. The selection follows a member into the fold and back to the anchor. Methods collapse(id), expand(id), isCollapsed(id), setFolds(list); event onFoldChange({ id, collapsed, fold, event }).
  • aggregateLinks: true — parallel ties of one pair and category drawn as one, value summed, the originals listed in the tooltip and kept in link.links.
  • laneCap: n — a lane with more than n nodes shows n: its n − 1 heaviest and a "+N more" node holding the rest (fold id lane:<lane>), opened with its +.
  • Time navigation in the flow view — timeframes (preset keys or { key, label, range }) and navigator, as on TimeSeries, over the ties' start/end. The navigator strip, with a time axis, shows how many ties are active per day, month or year (a tie without an end counts as still running, as setTimeWindow reads it); brush it to pick a period. Ties outside it dim. With navigation on, setTimeWindow() moves the view and the buttons follow; setTimeframe, setView, getView and onViewChange work as on TimeSeries.
  • RareCharts.MapFlow (experimental; src/charts/MapFlow.js, docs /charts/map/flow/). Built on Map — same geometry options, projections, zoom and theme — with the { nodes, links } contract of Graph and Sankey. A node stands at coords: [lon, lat] or at the centroid of its country's largest polygon. Each flow is a great-circle arc that bows to one side (A → B and B → A never overlap; parallel flows fan out), width by value (square-root scale, linkWidth), colour and dash by type (linkTypes), an arrowhead at the target. A legend of types turns them on and off (hiddenLinkTypes, linkLegend, setLinkTypesVisible()); setTimeWindow(from, to) hides (or dims, timeWindowMode: 'dim') flows outside the window and fades places left without any; fitTo: 'links' frames the places and their arcs instead of the whole map. Place labels give way to each other, heavier places first. Hover tooltips; click or Enter pins a flow's tooltip. A time scale like TimeSeries has: timeframes (era buttons with { key, label, range }) and a navigator strip with a time axis showing how many flows run over time — brush it to pick a period; setTimeWindow() then moves the view. Two demos: the opium triangle, and dollars outside America on a time scale (1957 / 1968 / 2025 / All).
  • Overview takes margin and axis — the navigators of the flow view and MapFlow span the drawing (no Y-axis gutter) and show a time axis under the strip; TimeSeries is unchanged.
  • barWidth (Bar, DualAxes; src/core/barLayout.js) — a bar width in px. On Bar: the width of a vertical bar, the thickness of a horizontal one, the whole column of a stacked bar. On DualAxes: the width of each bar, with series.barWidth for one series (series, then chart, then barWidthRatio); a cluster is the sum of its bars, centred on the date. With categories the bar stays centred in its slot (in date mode and on DualAxes the scale is inset by half a bar, see Changed); a width larger than the space per category or date is cut to it (a cluster narrows in proportion), so neighbours touch but never overlap. Anything that is not a positive number is ignored; an explicit width drops the 2px floor and 48px cap of Bar's ratio. Docs: Bar → Bar width and color, with a demo; Stacked Bar, Dual Axes and Combined tables.
  • Per-bar colour on Bar — a row's color fills its bar ({ label, value, color }, { date, value, color }), then barColor, then the theme accent; '' counts as no colour. setData repaints a bar whose colour changed or went away, and hover only dims it. Stacked bars ignore a value's color: segments keep their series colour.
  • Annotations on the dated Bar (annotations, annotationLabelHeight; docs /charts/bar/ → Annotations, with a demo). A vertical Bar fed { date, value } rows takes the markers of Line — points and ranges on dates, lines and bands on values — over the bars, on the chart's own scales. They follow timeframes, the navigator and setView, move with new data, take negative values, and clear with an empty window or setData([]); the pointer passes through them to the bars' tooltips. Labels get room above the plot as on Line (an explicit margin.top wins). A range between two bars' dates spans the bar centres — start and end it half a period out to shade whole bars — and levels do not widen the value axis (a level beyond it is not shown). Categorical, stacked and horizontal bars have no date axis: they draw nothing and warn once per chart.
  • theme.tooltip.header ({ text, bg }, both null by default) colours the row that names what is hovered: the date in Line, DualAxes and TimeSeries, the label in Bar, HierarchicalBar and Donut, the title in Map, MapFlow, Sankey and Graph. null keeps today's look (a date muted, a title bold); bg draws the header as a band across the top of the tooltip. A Donut slice label keeps its slice colour.
  • createTheme(overrides, base) — an optional second argument, the theme to merge onto: createTheme({ tooltip: { bg: '#000000' } }, RareCharts.darkTheme) keeps the rest of the dark tooltip.
  • Tooltip row classes (rare-charts.css): .rc-tooltip-header, -title, -muted, -sub, -kind, -value. The built-in tooltips are made of them, and a tooltipFormat can use them to match the default look and follow theme.tooltip; the tooltipFormat and linkTooltipFormat contracts are unchanged.
  • whenReady() on every chart — a promise that resolves with the chart once it has drawn what it loads: Graph its requests and layout, Map and MapFlow their geometry (also when the geometry fails to load; the error is logged). The other charts draw on setData(), so theirs resolves at once. Only Graph had it. A Map given no geometry source now warns in the console instead of staying silent.
  • window.RareChartsConfig = { injectStyles: false } for a strict Content Security Policy: set before the bundle, it stops the injected <style>, and the page serves rare-charts.css as a file (Installation → Strict Content Security Policy). Each release now publishes rare-charts.css next to the bundle in rare-charts, so a pinned CDN copy is available. A <link id="rc-base-styles"> stops the injection too.
  • graticule: true on Map draws a 10° grid of meridians and parallels under the regions, in theme.map.graticule. Off by default; not drawn with projection: 'identity'.

Changed

  • Nodes without hints in the flow view are laid out automatically instead of stacking in input order in column 0. Any position hint pins a node as before, so fully hinted traces — the docs demo, the data project's — look the same; layout: 'hints' brings back the stage-1 placement.

  • The flow demo folds the crowdfunding side with the library's fold instead of page code switching a filter, takes start/end from each tie's period, and navigates time with three chapter buttons and the navigator.

  • Chart subtitles wrap (all chart types; rare-charts.css → .rc-chart-subtitle) instead of being cut with an ellipsis; the title stays on one line. A long subtitle makes the header taller and the plot area that much shorter within the same height. Its line height is 1.2em, so a wrapped subtitle stays compact.

  • The legend has no padding of its own (.rc-legend): it lines up with the title and the plot instead of sitting inset.

  • Timeframe buttons sit flush right on charts without a Y-axis gutter (Map, MapFlow, the Graph flow view: .rc-chart-range-row--flush); line charts keep the 60px above their axis labels.

  • Chart text takes the chart font throughout (rare-charts.css): the flow view's node sub-lines and tie labels (were monospace), the navigator's time axis (d3's sans-serif default removed), and the page's own details panel — its headings no longer take the site's heading font.

  • The flow view's navigator spans the drawing: with the details panel beside it, the strip stops where the panel begins; a few px inside the card's edges keep the brush handles visible, and an axis label that would run past either end is dropped instead of cut. The strip spans the ties' dates exactly (it used to stop at the start of the last month, so the selection's right handle fell off the edge); Overview.setBrush() clamps to the strip.

  • Last-value labels sit 7px further left (Line, DualAxes; renderEndLabels places them 3px past the plot instead of 10px): values longer than four or five characters ($88.4K, 1,234.56) no longer run into the card's edge. The label may cover the last few px of its line.

  • Docs: note and controls are named wherever a chart page points to the common options, and the composed header-and-footer example on Settings now carries a note; Circular and Graph pages got the pointer they lacked.

  • Map keeps its projection after rendering and fits it to _fitObject() — internal hooks for MapFlow; its public API and output are unchanged.

  • Categories of ties resolve one way in every relation chart (core/links.js → resolveLinkType). Visible changes: in the flow view a tie without a category is now muted (it took the first palette colour) and is labelled "connection"; on ego/path/cluster views a type linkTypes does not describe takes a free palette colour (it was muted). Sankey keeps undescribed types muted, since its legend lists described types only.

  • MapFlow tooltipFormat is for places only; a country under the flows takes regionTooltipFormat (Map's { feature, item } payload).

  • The navigator lines up with the plot: its side margins follow the chart's own (they were a fixed 0 / 70 px); navigator: { margin } is merged side by side.

  • The library no longer loads fonts (rare-charts.css). The injected stylesheet dropped its @import of Google Fonts, so a page with RareCharts makes no request to fonts.googleapis.com / fonts.gstatic.com (on raredigits.art those faces used to replace the self-hosted Fira Sans and Cousine on every chart page, page text included). Charts use Fira Sans and Cousine when the page provides them — Rare Styles self-hosts both — and a system stack otherwise (system-ui … sans-serif, ui-monospace … monospace; theme.font and theme.numericFont fall back the same way). For the old look on a page without these fonts, add the <link> from Installation → Fonts and Rare Styles; for other fonts, set --rc-font-family / --rc-font-family-numeric with a selector that outranks .rc-chart (the library's stylesheet is injected last), such as :root .rc-chart. Semi-bold text is bold now, since no host ships a 600: the Graph breadcrumb, the "+N more" panel title, the map tooltip title.

  • The chart font reaches every part of the card: font-family is set once, on .rc-chart. Without Rare Styles the subtitle, legend, source and note took the page's font, and the Graph zoom/full-screen buttons the browser's button font; the Graph tool buttons and the timeframe buttons now take font: inherit (the timeframe buttons keep a 1.15 line-height). Nothing changes on Rare Styles pages.

  • Missing values in Line, DualAxes and TimeSeries leave a join, not a dip to zero: a null, '', boolean or non-numeric value is dropped (it was drawn as 0, true as 1), in TimeSeries.setData and appendPoint too. That covers blank CSV cells from fromCsv; a DualAxes bar series skips the date instead of drawing a zero bar. A dashed DualAxes series appears without the draw-in, as a dashed Line series already did.

  • Last-value plates on the light theme take the page background (theme.bg: --bg-color under Rare Styles, white otherwise) instead of always white, so on a grey page they no longer show as white chips.

  • The map ocean is transparent by default in both built-in themes (theme.map.ocean was var(--bg-color)): the page shows through, as the Map docs always said; under darkTheme it is no longer the page's light colour.

  • MultiChart's default gap is 32px everywhere — it was 16px on pages without Rare Styles.

  • rare-charts.min.js embeds its stylesheet minified (comments and whitespace removed, same rules); rare-charts.js keeps rare-charts.css as written.

  • Ids in a chart's <defs> have one per-chart format (rc-<salt>-<n>-clip, …-ts-grad, …-arrow-0). None was documented; the gradients keep rc-ts-grad / rc-ov-grad as classes to style them by.

  • Graph's model no longer bundles graphology-metrics: its unused internal centrality() and link() are gone, and the Graph page no longer says the model computes betweenness — node importance is degree (sizeBy: 'degree').

  • Docs: per-series options. The Line, Dual Axes and Combined tables list strokeDash and markers, markerShape, markerSize, markerFill, markerStroke per series; every markerShape row names all five shapes (triangle and cross were missing).

  • DualAxes with bars insets its time scale by half the widest bar or cluster (C-27): the first and last bars are drawn whole, lines start and end at the bar centres (about 5.5px per side on "Index and yearly change", 12px on the LTCM combined demo), and xPad is the gap from the plot edge to the outer edge of the edge bars. Annotation ranges and levels still reach the plot's edges, so a range can shade an edge bar whole. A chart without bars is unchanged. Bar's date mode is inset the same way, so its bars move inward by half a bar — up to 24px with the default ratio.

  • barWidthRatio on DualAxes is a share of the smallest gap between bar dates — it was the gap between the first two dates of any series, lines included. Regular data looks the same. Bars now follow their own dates: irregular dates get narrower bars that no longer overlap, and bars under a denser line series (monthly bars over a daily line) get wider ones — they were sized to the line's step.

  • The crosshair reads the plot padding as the nearest end of the view (Line, DualAxes): an edge bar shows its tooltip across its whole width, and hovering Line's 8px xPad gutter shows the edge point.

  • Tooltip typography lives in CSS; colours come from the theme as custom properties. Size (13px), weights and spacing are in rare-charts.css; theme.tooltip reaches it as --rc-tooltip-* properties set on the tooltip, and only data colours (series, slices, link categories) stay inline. A page rule that outranks .rc-tooltip, such as .rc-chart .rc-tooltip { font-size: 14px }, now restyles the tooltip, colours included — before, the inline styles always won.

  • Every secondary tooltip row reads theme.tooltip.muted (dates, percentages, counts, periods, shares — the stacked Bar's share of the total, a plain row before, is now muted like Donut's); they read the chart's theme.muted, and tooltip.muted was read nowhere. Its light default moved from #888888 to #666666, the chart's own muted, so the default look is unchanged. A page that set theme.muted to recolour its tooltips should set theme.tooltip.muted.

  • TimeSeries tooltip date is 13px with no gap under it, as in Line and DualAxes (it was 14px from theme.fontSize, with a 4px gap); the date format is unchanged.

  • Relation-chart tooltips share one tie layout: the MapFlow flow tooltip takes Graph's (the category above its label, value and period); the Graph node's group and per-type counts read as categories, as in the flow view; tooltips cap at 280px (Graph nodes were 260px, ties 300px); "+N more" is 11px.

  • Links in tooltips (a tie's sources) take the tooltip's text colour, underlined, while hovering as well as when pinned — they were the browser's blue, unreadable on a dark tooltip.

  • theme.fontSize is not used (its last reader was the TimeSeries date) and goes at 1.0. Of the theme's fonts only numericFont is read, as the tooltip font family, with font as its fallback.

  • Docs: the Dual Axes margin row gave the right margin as 92; it is 64 on both sides. The MultiChart page no longer says a panel can be "any other type".

  • Default number labels on Line and Bar. Linear value-axis ticks are labelled by their step: grouped numbers below 1,000, SI prefixes from 1,000 (one prefix for the whole axis), zero as 0 — 145 150 155 160 instead of 150 150 160 160, 0 0.5 1 instead of 0.0 500m 1.0, 0 0.5M 1M instead of 0.0 500k 1.0M. Line end labels and tooltip values take three significant digits (147, −0.6, 1.23k), so −0.6 no longer reads −600m. Bar's vertical, horizontal, dated and stacked axes follow the same rule. An explicit yTickFormat / xTickFormat wins; percent (+.2%, .0%) and log (.3~s) labels are unchanged.

  • TimeSeries picks its default date format from the span in view: %H:%M up to 36 hours (a tick at midnight names the day), %b %d up to 92 days (at most one tick a day), %b up to a year, %b '%y up to five years, %Y beyond. The 1M view read "Sep Oct Oct Oct" and the ALL view had no year. Bar's date axis, which repeated months the same way under its '%b' default, follows the same rule. An explicit xTickFormat wins.

  • Horizontal Bar value labels fade in at their places while the bars grow, instead of appearing at the bar base and jumping to the bar end.

  • A partial margin fills the sides it leaves out with 0, not the base chart's 8/70/16/0. With margin: { top: 10 }, Map, MapFlow, Graph and MultiChart got a 70px gutter on the right; a map now spans the card and its timeframe buttons stay flush right. Axis charts work out the sides they need, as before; Donut, Pie, Gauge, Sankey and Graph fill the card and do not use margin (Settings says so).

  • The header follows the card, not the window (rare-charts.css). .rc-chart is a size container, and the header stacks — buttons under the subtitle — on a card 460px wide or narrower, whatever the window. It used to stack on windows up to 768px, whatever the card: a narrow card on a desktop now stacks, and a 461–768px card on a tablet keeps its buttons beside the title. A chart inside a box that shrinks to its content (an inline-block, a flex-row item) needs a width.

  • Crowded date labels thin out on every time axis (Line, DualAxes, Bar with dates): the overlap check halves the tick count it asks of d3, not the labels drawn — a time scale may answer six with twelve quarter ticks, so the labels used to stay crowded. Bar's date axis now uses the same shared axis.

  • The plot keeps at least 80px. When the title, subtitle, buttons, legend and footer wrap on a narrow card and would leave the plot less, the card grows past height by the difference and returns to height once they fit. The plot used to shrink to nothing. A height the page set on the card is left alone.

  • HierarchicalBar label layout. From a plot 480px wide a row reads name → bar → value: names in a column of up to 40% of the width, flush against the bars (a long name wraps once, then ends in an ellipsis; labelAlign: 'left' lines the names up at the left edge, indented by depth), bars from one zero line shared by every row, values in a right-aligned column. Narrower, the name keeps its line above the bar and is shortened to the width, so long names no longer run past a phone-width card. Stacked, depth indents the name only, not the bar; parent rows are semibold; a gap sets each branch group apart. The default rowHeight is 28 side by side and 44 stacked, so chart heights change. The portfolio demo drops its root row (the total is in the title) and its labelMaxLength.

  • MultiChart rebuilds a panel at the breakpoint. The narrow layout depends on the container width alone (0 < width ≤ mobileBreakpoint); a grid with columns ≤ mobileColumns used mobileOptions on any screen. Crossing the breakpoint used to patch a panel's options, so height and margin from mobileOptions applied only in part — the plot was resized but not moved, and the card kept its height. Each panel with mobileOptions is now built again with the options of the new side and its last data: mc.charts[i] is a new instance, state set through the panel's own methods starts over, and with animate on its entry plays again.

  • Map hover lightens a region's own fill: it moves theme.map.hoverBrighten − 1 of the way towards white (1.3, so 30%; 1.2 in the dark theme; 1 turns it off) — black lightens too, nothing turns pure white, and a fill already very light darkens a little instead. Every region with data used to hover to matchFill mixed 16% toward white, whatever its own colour. hoverFill still wins.

  • Graph flow view keyboard: nodes share one Tab stop instead of one each, and the ties have their own stop, before the nodes. A stop is the selected item, else the one focused last. ↓ / ↑ continue into the next / previous lane, so every node can be reached; Home / End go to the first / last node or tie.

  • RareCharts.d3 is a documented subset of the bundled D3, not the whole namespace: format, formatPrefix, timeFormat, timeParse, utcFormat, utcParse; sum, min, max, extent, mean, range; scaleLinear, scaleTime, scaleLog, scaleOrdinal; color, rgb, hsl, interpolate; timeDay, timeWeek, timeMonth, timeYear, utcDay, utcWeek, utcMonth, utcYear — every function the docs and examples use. The minified bundle is about 47 KB smaller gzipped. Breaking for a page that took anything else from RareCharts.d3 (selections, shapes, geo): load D3 itself (README, Installation). (K-13)

  • One rule for formatter arguments, backward compatible: the formatters of Line, DualAxes, TimeSeries, Bar, HierarchicalBar, Donut/Pie, Gauge and Map get the role fields label, value, date, color, percent, series (whichever apply) — on the object they already receive, or, where the first argument is a number, a data row or a tree node, as the next argument (Gauge centerText: the fourth). The relation charts keep their own payloads (Sankey's valueFormat takes only the number). Settings → Formatter arguments has the rule and a per-class table. (K-09)

  • Overview is a documented public class (Time Series → Overview, standalone navigator) and reads dates as the charts do — a Date, an ISO string or epoch ms, in the rows, extent and setBrush(); string dates used to draw nothing. (K-04)

  • Donut drillTo(child) is documented next to drillUp() and drillToDepth(): it takes a child of the level shown — the page's own object, its id or its label — and draws what a click draws; generateMockPrices() stays exported as a demo helper outside the stability guarantee. (K-21, K-04)

  • Relation data is read in one place (normalizeRelationData in core/links.js): Graph (every view and its model), MapFlow and Sankey keep their own rule for ends that name no node (Graph creates the node, MapFlow drops the link with a warning, Sankey drops it when nodes is given and derives the node otherwise), and Graph's model no longer reads its links twice. Link ids keep their format, now frozen for 1.0: a link's own id wins; otherwise source→target#n (MapFlow, Sankey, the flow view) and source→target|type (Graph's ego/path/cluster views, one tie per pair and type across loads). The flows alias works in every Graph view and in memorySource. (K-07)

  • Graph.js is split the way the flow view was: the ego/path/cluster drawing (graph/views/network.js), the card chrome (graph/chrome.js) and the default tooltip and details HTML (graph/tooltips.js); Graph.js keeps the options, the source queue, view switching and the public API (2,199 → 955 lines). No behaviour change. (D-11)

Deprecated

  • viewSteps, the old name of timeframes: it still works (timeframes wins when both are set) and warns once per chart; removal is planned for v0.9.9. (K-04)

Removed

  • The rest of the D3 namespace from RareCharts.d3 (see Changed). (K-13)
  • theme.service — undocumented; its only use was the plate behind last-value labels, now theme.bg. A theme that set service should set bg.
  • Docs-page CSS no longer ships in the library: .rc-demo-* (the Visual options controls) and .price-chart-* (the TimeSeries page's price header and stats) moved to the site's stylesheet; the unused .rc-demo-btn* rules and the dead aliases .range-btn and .price-chart-range-bar are gone (the library has emitted .rc-range-btn / .rc-chart-range-bar since March). A page that styled its own markup with these classes needs its own CSS.
  • Four unused map files (4,610,774 bytes): data/maps/countries.json, data/maps/world/level-0/world-atlas/countries-10m.json and data/maps/world/level-0/disputed/visionscarto-world-atlas/{110m,50m}.json. No page or example used them, and neither the README nor the docs offered them. They leave raredigits.art/assets/charts/data/ and rare-charts from this release on; earlier tags keep serving them, and the same files are published upstream (cdn.jsdelivr.net/npm/world-atlas@2/countries-10m.json, cdn.jsdelivr.net/npm/visionscarto-world-atlas@1/world/110m.json, 50m.json). The kept countries-110m.json and countries-50m.json now ship with world-atlas's ISC notice beside them.

Fixed

Found by a library-wide audit before the release; the fixes come with regression tests, each checked to fail without its fix.

  • Input — parseDate no longer lets an Invalid Date, NaN, null or false through (Line used to crash on them, or plot 1970). Time series are drawn in date order whatever order they arrive in. TimeSeries.setData parses ISO-string dates and copies its input; appendPoint no longer changes the caller's array. The pre-freeze groundwork release. Added

  • Hiding an axis now reclaims its margin (src/charts/Line.js, Bar.js, DualAxes.js, TimeSeries.js). [v0.9.7] — 2026-06-19 — Footnotes

Finishes the chart footer. Two new attribution slots — an editorial note and a linkable, multi-part source — so the interpretive line and the data credits live inside the component instead of as hand-built markup glued around it. Plus a set of edge-rendering fixes (axis titles, web-font timing, flush bar labels) that surfaced while wiring a real client chart.

Added

  • source accepts links and multi-part attribution (src/core/Chart.js → _renderAttribution, rare-charts.css). Beyond a plain string, source now takes { text, href } (a single linked attribution) or an array of parts — strings render as plain text, { text, href } objects as links — so a footer can mix several linked and unlinked sources on one line (e.g. Source: NASDAQ, Bloomberg, Internal calculations with the first two linked). Links inherit the source text color (set apart by an underline, so they adapt to light/dark theme), open in a new tab with rel="noopener noreferrer", and an array source wraps instead of truncating so every attribution stays visible. String and HTMLElement sources are unchanged. Flows through MultiChart's shared footer. Removed from the backlog.
  • note text slot on every chart (src/core/Chart.js, rare-charts.css). A new footer option renders a <p class="rc-chart-note"> below the source line in theme.muted, for disclaimers, data caveats, and editorial context. Accepts a string or an HTMLElement. This was the recurring anti-pattern the settings page warned about — interpretive captions hand-built as a stray <div> glued under the chart container — now an in-component slot the chart owns. Long notes wrap (including unbroken tokens like URLs, via overflow-wrap) and the plot shrinks to keep the note inside the card rather than overflowing it. Also flows through MultiChart's shared footer. Documented at /charts/settings/; removed from the backlog.
  • Machine-readable bundle header + RareCharts.VERSION (src/index.js, build banner in package.json). The minified bundle is opaque to anyone — human or LLM — handed only the file. The header now states the global, the new RareCharts.<Type>(selector, options).setData(data) construction pattern, the full list of chart classes, the container requirement, that d3/CSS are bundled, and that external data loads via the fromJson/fromCsv/fromApi/fromArray adapters — so consumers stop guessing class names or hardcoding structure. VERSION is also exported as a runtime constant for build identification. Pairs with the text-slot conventions added to /charts/settings/.

Changed

  • Axis titles clip to their margin instead of running off the chart (src/core/renderHelpers.js → renderAxisTitles, src/charts/DualAxes.js, src/core/utils.js → warnAxisTitleClipped). y1Title / y2Title are now measured by rendered pixel width against the available axis margin (its exact overflow-clip boundary) and trimmed with an ellipsis only when they would actually be cut off — narrow glyphs in a terse title like N · K HLX, and the uppercase transform applied via CSS, are accounted for as they render, so a label that fits (e.g. Inflows) is left intact. The full text is kept as a hover <title>, a one-time console hint fires, and axisTitleMaxLength caps the length explicitly.

Fixed

  • Horizontal bar value-axis end labels no longer clip at the chart edge (src/charts/Bar.js). When the value axis sits flush against the card (margin.left / right = 0), the centered first/last tick label (e.g. 0) was half-cut by the card's overflow clip. [v0.9.6] — 2026-06-14 — Confidence Bands

Adds a band (confidence-ribbon) primitive to Line and the supporting legend and tooltip work to make it readable. Targeted at forecasts and any figure where a single line would overstate precision. Also corrects two strokeDash defects that were documented but didn't work.

Added

  • band series type on RareCharts.Line (src/charts/Line.js, src/core/seriesPath.js). A series marked type: 'band' with { date, lower, upper } points renders a filled ribbon between the two boundaries at each x — for confidence intervals (P10–P90 cones), min/max envelopes, and error bands. The band draws behind every line and area, both bounds participate in the Y scale, and it mixes freely with ordinary line series in the same setData call. Fill uses the series color at fillOpacity (default 0.16). Detected by type: 'band' or by the presence of lower/upper on the first point. Documented at /charts/line/band/ with two examples (examples/line/line-chart-band.js, examples/line/line-chart-forecast.js).
  • Band readout on hover (src/core/Crosshair.js). A band reports its range in the crosshair tooltip as lower – upper (e.g. P10–P90: $1.95M – $3.65M). It draws no crosshair dot — a band has two edges and no single point, so a dot would be ambiguous; markers and end labels skip it for the same reason.
  • Legend swatch types (src/core/Chart.js, rare-charts.css). A legend entry's type now selects its swatch so the legend matches the on-screen encoding: 'band' → filled square, 'dashed' (or dash: true) → dashed rule, 'dot' / 'bar' → dot (unchanged), default → solid rule. Needed because a forecast draws actuals, P50, and the range in a single hue, where the legend has to carry the distinction.

Changed

  • The crosshair only reports a series where its data covers the cursor date (src/core/Crosshair.js). A partial series — a forecast band or a projected line that starts part-way along the axis — no longer snaps its nearest endpoint across the whole width; it stays silent outside its own date range. When nothing is under the cursor, the crosshair line, dots, and tooltip clear. This affects every chart that uses the crosshair, not only bands — in practice it only changes charts whose series span different date ranges.

Fixed

  • Per-series strokeDash was documented but never applied. The field was listed in the Line options table and read during render, but _normalizeData dropped it, so a per-series dash pattern had no effect. It is now carried through and works.
  • resolveStrokeDash rejected raw dash-array strings (src/core/utils.js). The options table implied a value like '4,3' was accepted, but only the named presets ('dashed', 'dotted', 'dashDot', 'longDash') resolved — any raw string fell through to null. A numeric dash-array string (e.g. '5,4', '4 3') is now passed through as-is.
