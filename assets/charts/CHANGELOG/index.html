Stop thinking about decorations, start thinking about the value.

The only thing that matters is the data your audience came for. Design, layouts, make-up and decorations are just your tools to highlight the value.

Imagine you have 30 secs to pitch your data. What would you say? What decision maker need to know? How would you present it? What would you highlight? What would you hide?

That's it. That's the only thing that matters. Delete the noise. Make your audience satisfied.

RareCharts Changelog

RareCharts — Changelog

All notable changes to RareCharts are documented in this file. Format follows Keep a Changelog. The library follows semantic versioning.

Roadmap and planned features: raredigits.art/charts/backlog.

This file begins tracking at v0.9.6. Earlier versions were released without an itemized changelog.

Release checklist — the version has a single source of truth:

  1. Move the accumulated [Unreleased] entries in this file under a new ## [vX.Y.Z] — date — Title heading.
  2. Bump version in assets/charts/src/version.json. That value flows automatically to the runtime RareCharts.VERSION (src/index.js), the build banner (scripts/build-charts.mjs), and the docs version label / CDN pin (_data/versions.js) — nothing else to edit.
  3. Push to main. CI does the rest: runs the tests, rebuilds the bundles from source (they are not committed to git), syncs raredigits/rare-charts, and pushes the vX.Y.Z tag — jsDelivr resolves @latest and version pins from those tags. The sync only fires for a version that is not yet tagged, so pushes between releases never reach CDN consumers.

Whenever the public API surface changes (new chart class, new adapter, the construction pattern), update the banner's machine-readable header in scripts/build-charts.mjs.

A second patch on top of v0.9.8_4, again for the Rare Styles content starter: one visual fix on horizontal Bar. Flows II stays v0.9.8_5.

[v0.9.8_4_1] — 2026-10-19 — Bar Value Labels

A patch on top of v0.9.8_4 with one Bar fix, found while building the Rare Styles content starter. Nothing else changes; charts whose value labels already fit render exactly as before. Flows II stays v0.9.8_5.

Fixed

  • A short bar's value label was clipped (src/charts/Bar.js, horizontal, showValues: true). A label flipped inside its bar whenever the space past the bar end was under valueInsideGap, whether or not it fit inside. A small negative bar next to the left edge of a phone-width plot got its label squeezed into a bar a few pixels wide, so -0.2 read as -0. A label now goes inside only when it fits there; otherwise it sits past the bar end — left of a negative bar, right of a positive one — and the value axis widens on that side until the label fits (at most 30% of the plot width per side). Charts whose labels already fit are unchanged.

[v0.9.8_4] — 2026-10-19 — Log Scale

A small release out of turn, for a consumer that plots a long-horizon index and switches periods by swapping data: a logarithmic Y scale on Line that can be turned on and off between setData() calls, and linear ticks that stay inside the data. Flows II, the composition tail and the rest of the scales release move one slot down (v0.9.8_5 / _6 / _7) with their content unchanged.

Added

  • yScale: 'log' on Line (src/charts/Line.js, src/core/utils.js, docs /charts/line/ → Logarithmic scale). Ticks fall on powers of ten — 10, 100, 1k, 10k, 100k (thinned to every 2nd/3rd power past twice yTicks); a range narrower than two powers gets 1-2-5 steps (20, 50, 100), a narrower one still gets linear steps. Labels drop trailing zeros (1k, not 1.0k). The margin above and below the data is a factor — 8% of the data's log span on each side — so both ends get the same room instead of the axis bending at the bottom. Values ≤ 0 are skipped (lines, bands, markers, crosshair; the line joins its neighbours) with one console warning per setData(), never drawn as NaN; horizontal annotations at or below zero are dropped and an area fills down to the bottom of the plot. Explicit yTickValues keep working (non-positive ones are ignored).
  • Line.setYScale('log' | 'linear') — switches the scale and redraws; returns the chart, so chart.setYScale('log').setData(all) changes scale and data in one paint. Log on the full history, linear on the last year.
  • Helpers linearTickValues, logTickValues, logPaddedDomain in src/core/utils.js.

Fixed

  • Line Y axis ran past the data (src/charts/Line.js). Ticks were built as exactly yTicks steps up from the minimum, and the domain was stretched to the last one: a year of data topping out at 193 got an axis to 400 and a line squeezed into the lower half. Ticks now fall on d3's 1-2-5 steps inside the padded data range, and the domain is that range — yTicks is a target count, not a quota (the step decides: 3–6 ticks for the default 4). Charts with explicit yTickValues are unchanged. Bar keeps its own tick logic.
  • The controls row overlapped the X axis (src/core/Chart.js). The drawing's height did not count the controls slot added in v0.9.8_3, so the row sat on top of the axis labels; it is now subtracted like the header and footer.
  • Demo selects had the browser's light border (rare-charts.css → .rc-demo-select, /charts/line/visual-options/). They now get a black border matching the control cards.

Size

Minified bundle 599,769 → 600,672 bytes (+903, +0.15%); gzip 179,916 → 180,248 (+332). Measured on local builds of v0.9.8_3 and this release, banner excluded.

Removed from the backlog

Logarithmic Y scale on Line. The same option on TimeSeries and DualAxes stays in the backlog for v0.9.8_7.

[v0.9.8_3] — 2026-10-16 — Flows I

The relation release. Two new ways to draw what moves between things — a Sankey diagram and the Graph flow view for money trails and supply chains — on one shared link contract, plus a Graph that keeps every tie between a pair, explains a node or a tie in a details panel, and holds up under a real walk-through: grid layouts everywhere but the route view, a canvas that fits what it can show, full screen, footer tools. Sankey and the flow view are experimental, outside the 1.0 promise.

Added

  • Graph details panel (src/charts/Graph.js, rare-charts.css → .rc-graph-details). Option details: true lets the library show the hovered or selected node or tie — name, group, connections with their labels and values, period, sources as links; in the ego view the focused node when nothing is hovered (custom content via detailsFormat({ node, link, view })). An element or selector gives the slot to your own panel, filled from onSelect. The panel sits beside the drawing when the card's content is at least detailsBreakpoint (1000 px) wide and the drawing keeps its own minWidth next to it — the layout narrows by detailsWidth (300 px) — and below the drawing otherwise, the card growing by detailsHeight (200 px) so the graph keeps its height.
  • Controls slot for every chart (src/core/Chart.js, rare-charts.css → .rc-chart-controls). Option controls (element or selector): your own checkboxes, sliders or selects are moved inside the card between the drawing and the footer, styled as a compact row; their listeners keep working.
  • Flow view: hiddenLinkTypes (src/graph/views/flow.js). Tie categories hidden at start; the legend lists them dimmed and turns them on. A node whose ties are all hidden by the legend is hidden with them (a decoy without its fake transfers would float), and the legend's list comes from the page's filter only, so a hidden category can always be turned back on.
  • Graph full screen (src/charts/Graph.js, rare-charts.css → .rc-graph--fullscreen). A ⛶ button in the footer tools opens the graph on the whole screen (Fullscreen API; a fixed overlay where the API is unavailable or blocked); Esc or ✕ closes it. The graph re-lays out for the new size, so a capped neighbourhood shows more. Option fullscreen (default true), method toggleFullscreen(on?).
  • Graph view: 'flow' — a trace in ordered lanes (stage 1, experimental) (src/graph/views/flow.js, src/charts/Graph.js, docs /charts/graph/flow/). For money trails, supply chains and address investigations: nodes stand in lanes (lanes, laneBy) and are placed from data hints — row around the main line, col sub-columns, exact x/y fractions; unhinted nodes take the next free row. Directed ties, several per pair (opposite directions fan apart), width from linkWidth (sqrt of value by default), color from linkColorBy + linkTypes, dash from the type or linkDash, arrows in the tie's color, labels placed clear of each other. Node shapes per kind (circle, square, diamond, stack, or an SVG path), group colors and legend, sub captions, terminal markers, group outlines (hulls). setFilter, setTimeWindow (dim or hide), setLinkLabels, setHulls redraw without moving anything; select/clearSelection and onSelect({ node, link }) drive an external details panel; keyboard: Enter selects, arrows walk ties and lanes. minWidth scrolls narrow containers sideways. Automatic in-lane layout, aggregation and collapsible groups follow in the next release.
  • Sankey — new chart type (experimental) (src/charts/Sankey.js, src/core/sankey.js, docs /charts/sankey/). Flow diagram over the shared { nodes, links } contract: nodes in columns, band width = value. Own deterministic layout (columns by longest path, manual column override, nodeAlign, nodeSort with a stable input-order default, relaxation, collision resolution); cycles throw with the cycle named; invalid values and unknown nodes are dropped with warnings; repeated pair+type flows are summed. Band colors by source, target, type (with legend) or gradient. Hover highlights a node's or band's flows; click a band — or Enter on a focused node — pins its tooltip. orientation: 'auto' turns the diagram 90° on containers ≤ 480 px wide (rows grow by rowHeight). Labels sit right of their node with a measured gutter for the last column, and are cut with an ellipsis to the room available; full names stay in the tooltip and accessible names. A visually hidden table lists every flow (tableFallback). Outside the 1.0 stability promise.
  • Several ties between one pair, and ties you can open (src/graph/model.js, src/charts/Graph.js; Graph is experimental). The model keeps every tie between two nodes — family, investment and employment between the same pair no longer collapse to whichever came first — and draws them as parallel arcs (more than three collapse into one line with a +N badge listing them all). Legend filtering isolates a type's arc instead of hiding the pair. Ties are now interactive: hover shows a tie tooltip (endpoints, type, label, value, period, sources), click pins it so links inside can be followed; custom rendering via the new linkTooltipFormat({ link, source, target }). Links accept from/to as endpoint aliases and an optional id.
  • Shared link layer (src/core/links.js) for the relation charts: link normalization (aliases, stable ids), time on links (start/end; numbers below 10000 are years), time windows (hide/dim), value → width scales. Used by Graph now; Sankey and the Graph flow view build on it.
  • fitTextNode moved from Donut to src/core/renderHelpers.js for reuse (Sankey labels); .rc-sr-only utility in rare-charts.css.
  • Pinnable tooltip (src/core/Tooltip.js, rare-charts.css → .rc-tooltip.is-pinned). Opt-in pin()/unpin(): the tooltip stays put, takes pointer events and wraps; it closes on an outside click or Escape. Hover show()/hide() are unchanged for every chart.

Size

Minified bundle 544,951 → 600,678 bytes (+55,727, +10.2%); gzip 163,911 → 182,209 (+11.2%); Brotli 138,291 → 152,978 (+10.6%). Measured on the published files (jsDelivr, @v0.9.8_2 vs @v0.9.8_3, banner included). The growth is the two new relation views (Sankey, Graph flow), the shared link layer, and the Graph details panel, full screen and footer tools.

Removed from the backlog

Sankey; directed and multiple graph relations (several typed ties per pair). The Graph flow view's second stage — automatic layout, aggregation, collapsible groups — stays in the backlog for v0.9.8_4.

Changed

  • Graph.setData() no longer draws a throwaway default view (src/charts/Graph.js). setData() still focuses the best-connected node by default, but a focus(), connect() or overview() chained in the same tick now replaces that default instead of running after it: graph.setData(data).focus(id) fetches and renders id once. Previously the best-connected ego was built, rendered and immediately discarded. No whenReady() is needed between setData() and the first view call — and adding one now costs that extra default render. whenReady() after setData() alone still resolves after the default ego is drawn.

Fixed

  • Graph ego view piled a single-category neighbourhood into one corner (src/graph/layouts/ego.js). The grid anchors each category to a corner; when one category held almost every node it had nothing to share the canvas with. Now, when a category holds more than 80% of the nodes (and there are at least six), that category is anchored at the ego and fills the same grid from the centre out, first ring nearest — a centred rosette with no overlaps.
  • Cluster view overlapped large communities (src/graph/layouts/cluster.js). Meta-nodes stood on a circle, and big ones ran into each other. They now stand on a grid like the ego view — largest community in the centre, the rest spiralling out — and ties in both grid views bow slightly so they never run straight through the nodes between them. Only the path view keeps its own route layout.
  • Side details panel drifted off the drawing; legend ran under it (src/charts/Graph.js). The panel was placed by offsetTop, which an <svg> does not have, and before the legend settled; it is now measured from the drawing's box after the draw, so it matches the drawing's top and height exactly. With the panel beside the drawing, the legend and breadcrumbs stop where the panel begins.
  • Flow demo generalised (examples/graph/graph-flow-demo.js, /charts/graph/flow/): neutral names (owner wallets, DEX, bridge, crowdfunding, project team, exchange, project token) instead of the investigation's own; no controls row: clicking the Crowdfunding node closes or reopens its side, open by default (page code on onSelect), the look-alike address is the legend's "address poisoning" category, hidden at start; the time slider is gone (time navigation is planned for 0.9.8_4).
  • Path view: route captions overlapped the endpoint's context fan (src/graph/layouts/path.js, src/charts/Graph.js). "3 hops · shortest" / "4 hops" were pinned to the left edge — exactly where the first endpoint fans out its other connections. Captions now sit on their route, above its first intermediate node (or the middle of a direct tie).
  • Wrapped legends were spaced like separate paragraphs (rare-charts.css → .rc-legend). One gap served both axes; wrapped lines now sit 2 px apart with a tighter line height, items keep their horizontal spacing.
  • Graph legend items grew a button frame on hover (rare-charts.css). A host stylesheet's button:hover (Rare Styles adds a border and background) outranked the chart's own single-class reset. Legend items, "Show all", breadcrumbs and the +N more / hidden · restore notes now stay text-like in every state — only the cursor changes; keyboard focus keeps its outline. Hidden-node list rows keep their hover tint without the border.
  • A click with a slight tremor threw a Graph node across the canvas (src/charts/Graph.js → _dragBehavior). The drag had no subject, so d3 used the bare node datum (no x/y) and the first pixel of movement placed the node at an unrelated point — sometimes off the canvas, leaving its ties pointing into nowhere. The drag now starts from the node's current position and moves with the pointer, and movement under 6 px counts as a click.
  • Hover rings stuck on nodes after a recenter (src/charts/Graph.js). The recenter moved a node out from under the pointer before its mouseout; rings are now cleared on every draw.
  • Graph hid nodes it had room for (src/graph/layouts/ego.js → egoCapacity, src/charts/Graph.js). The capacity cap assumed 74 px rows while the grid, spread over the height, fits rows of ~50 px — so a 63-node neighbourhood lost 8 nodes on a canvas with empty cells. Cap and grid now share one cell rule (96 × 50 px), and spare cells are kept only while the canvas has them.
  • Graph notes moved off the canvas (src/charts/Graph.js). +N more and N hidden · restore were drawn in the bottom corners of the drawing, crowding the nodes there; they are now buttons in the footer tools next to zoom. Next to a dominant category, minority categories sit halfway out towards their corner instead of on the canvas edge.
  • The hidden-nodes list opened in the wrong place (src/charts/Graph.js). It is positioned against the chart card, which lost position: relative when the zoom controls moved to the footer; restored, and the list now opens bottom-right above the footer — picking a node recenters on it again.
  • Graph cut off its bottom row after a navigation (src/charts/Graph.js). The breadcrumb trail (and a legend that changed height with the view) appeared after the layout was computed and took height from the drawing, so the last row ended up below the edge. The graph now checks the drawing size after its chrome settles and re-lays out once if it changed.
  • A single-category ego piled up in the middle of a wide canvas (src/graph/layouts/ego.js). Grid cells are now at least ~96 px wide, the centred fill grows in the canvas's proportions instead of as a circle, and ego labels are cut to the cell width (full text in the tooltip).
  • Docs: recommended sizes for Graph views (/charts/graph/ → Sizing): the 96 × 74 px cell rule, what height covers, recommended width/height per view and how to handle bigger neighbourhoods and narrow screens.
  • Graph views floated in wide top and bottom margins (src/graph/layouts/ego.js, cluster.js, path.js). The grid kept spare rows and padding, leaving 40–60 px bands above and below the drawing; the rows in use now span the canvas from just under the top edge to just above the bottom (room for the bottom labels only). Path routes spread further apart.
  • Graph breadcrumbs broke onto one line per level (rare-charts.css). A host stylesheet that makes every <button> a block (Rare Styles does) stacked the trail; its buttons are now inline.
  • Graph zoom controls covered the canvas (src/charts/Graph.js, rare-charts.css). The +/−/⟲ buttons moved from an overlay in the bottom-left corner of the drawing to the footer row, right-aligned next to the source line; a chart without source or note gets a footer row for them.
  • Graph +N badges hid under node labels (src/charts/Graph.js). A collapsed pair's badge now takes the first spot along or beside its tie that covers no node and no label, and is drawn above the nodes with a halo.
  • Flow view polish (src/graph/views/flow.js): tie labels avoid node shapes, node captions and group labels, and draw above the nodes; node captions are cut to their column's width (full text in the tooltip and accessible name); the bottom row keeps clear of the zoom controls; the legend lists only tie categories the current filter shows (plus any toggled off).
  • Graph hover never faded the rest of the graph (src/charts/Graph.js → _highlight). Focus + context set the opacity attribute on nodes, but the enter/update transition sets the opacity style, which wins — so the fade was computed and never shown. Now applied as a style; links were unaffected.
  • Graph arrow markers collided between instances (src/charts/Graph.js). Marker ids were rc-arrow-<type>, so a second graph on the page could resolve the first one's markers; ids now carry a per-instance suffix.
  • Investigated: “empty canvas after setData() → focus()” (field note 2026-07-31). Not reproducible as a queue race — both calls were already serialized, verified in jsdom, in a real browser and on the reporting site's own dataset. The observed blank canvas comes from a page that is not being painted (background tab, hidden pane): nodes enter at opacity 0 and the fade-in, like ResizeObserver, waits for the next paint; the graph completes as soon as the page is visible. The change above removes the double render that made it look intermittent. Regression tests: test/graph-ready.test.js.

[v0.9.8_2] — 2026-07-22 — Composition & Hierarchy

The composition release: stacking arrives on Bar, and tree-shaped data gets a first-class contract with two views over one shape — a new HierarchicalBar outline and an interactive drill-down mode on Donut, both fed by a shared normalizer. Around them, the circular charts grew up: outer labels stopped overlapping and overflowing, the gauge learned the speedometer look (any sweep + a needle), and a real Bar animation race was found and fixed. Stacked area (Line) and DivergingBar from the original plan move to v0.9.8_3.

Added

  • Stacked bars — a mode of Bar (src/charts/Bar.js). Hand Bar series-major data [{ name, values: [{ label, value }] }] and it stacks segments per category (d3-stack underneath): both orientations, stacked: 'percent' normalizes every bar to 100%, a legend is auto-built from series names, and each segment gets a tooltip { name, cat, value, total } with its share of the category total. Categories are the ordered union of series labels — a series that skips one contributes nothing there. Values are non-negative by contract (signed comparisons belong to the future diverging bar). Value-axis ticks divide the niced domain into exactly the requested yTicks/xTicks intervals — d3's "approximately count" could nearly double the density (domain [0, 120], count 4 → 7 ticks). Covered by test/bar-stacked.test.js; documented at /charts/bar/stacked-bar/. Removed from the backlog.
  • RareCharts.HierarchicalBar — tree outline (src/charts/HierarchicalBar.js). New class: one row per node, indented by depth, each with its own bar on a shared value scale — the linear view of a hierarchy (a portfolio into asset classes into holdings). Takes one root or an array of roots; parent rows carry their subtotal; the root renders as a neutral total, each top-level branch takes the next palette color and descendants inherit the hue with a per-level fade; a surfaced remainder draws muted; a value: null node renders as a ? placeholder. Options: showRoot, maxDepth, rowHeight/indent/barHeight, showValues/valueFormat (the tooltip respects it too), missingGlyph, labelMaxLength, and the normalizer pass-throughs. Covered by test/hierarchical-charts.test.js; documented at /charts/bar/hierarchical-bar/. Removed from the backlog.
  • Donut drill-down (hierarchy mode) (src/charts/Donut.js). Passing a single root object instead of a flat array turns the donut into an interactive drill-down over the same tree contract: it opens on the root's children, clicking a slice with children descends, the center (or a breadcrumb) goes back up — drillTo() / drillUp() / drillToDepth() are public. Breadcrumbs appear only once drilled in, flush with the chart's left edge; the center readout follows the focused node; a surfaced remainder draws as a muted slice; named-but-undisclosed children (value: null) are counted in a "N not disclosed" note rather than drawn. The flat array path is untouched. Documented in the Drill-down section of /charts/circular/.
  • Shared tree normalizer (src/core/hierarchy.js). One contract for every hierarchy consumer (and the future spatial Hierarchies): authored nodes { label, value?, color?, children?, remainderLabel? } with a tri-state value — a number > 0 is disclosed, an explicit null is kept as a missing placeholder excluded from every sum, anything else drops the leaf. A parent's stated value is authoritative and may exceed the sum of its children; the difference is a genuine remainder, surfaced as a synthetic child only via a node's remainderLabel or the chart-level showRemainder: true — never silently. Children exceeding the stated value flag overflow and warn (or throw under strict: true). Identity is assigned in a second top-down phase, so duplicate sibling subtrees and a real node colliding with a synthetic remainder still get distinct ids. 25 tests in test/hierarchy.test.js.
  • Gauge: speedometer needle and any-sweep geometry (src/charts/Gauge.js). needle: true draws a pointer pivoting on a hub at the dial center, animated to the value together with the fill; the center readout moves below the hub, dial-style; needleColor overrides the theme text color. Works with any startAngle/endAngle sweep — the half-circle automotive look is ±Math.PI / 2. Documented in the Speedometer section of /charts/circular/.
  • Donut/Pie outer labels: collision handling (src/charts/Donut.js). Leader-line labels now resolve overlaps: per side, rows are spread apart to a minimum gap (small adjacent slices no longer overprint), each label truncates with an ellipsis to the room between its anchor and the chart edge (the full text stays in the tooltip), and the center readout fits the hole — the value shrinks its font down to a floor instead of poking out, the secondary line truncates. Covered by test/circular-fit.test.js.

Fixed

  • Bar entry animation raced the layout and froze bars short (src/charts/Bar.js). When the first render landed while the header was still settling (fonts loading, flex layout), bars animated toward a stale plot height and stuck at a fraction of it — re-renders were swallowed by the once-per-instance guard, which was only set on transition end (an event that never fires for an interrupted transition). The guard is now set synchronously and re-renders interrupt() the in-flight tween and finalize to the current scale. Applied to all three bar geometries (categorical vertical/horizontal and time-series).
  • Gauge center label clipped on shallow arcs (src/charts/Gauge.js). For sweeps ending near ±90° the circle center sits at the drawing's bottom edge, and the label below it fell outside the svg. The radius/centering math now reserves room for whatever hangs below the circle center — the arc's own bottom or the text block — so nothing clips; deep arcs (the ±135° default) keep their previous geometry to within a pixel.

Changed

  • SVG text styling moved from inline attributes to the stylesheet (rare-charts.css, all chart classes). Chart code no longer sets font-family/font-size per element (~60 inline .style() calls removed); the svg inherits the small text size, .rc-axis / .rc-axis-cat classes give value and category axes their numeric/regular families (overriding d3-axis's own font-size="10"/font-family="sans-serif" group attributes), and numeric text (bar values, donut percents, center totals) is covered by per-class rules. Computed sizes (donut/gauge center) and behavioral styles (cursor, opacity, pointer-events) stay in JS. No visual change.
  • Docs: chart cards host the chart element itself. Example containers across the bar, stacked, hierarchical, and circular pages moved the card classes onto the chart div (the pattern the standalone examples already used), so axis and outer labels breathe into the card padding instead of clipping at the svg edge. The drill-down example lives in its own examples/pie-and-donut/donut-drilldown.js.
  • Build banner lists the new class (scripts/build-charts.mjs). HierarchicalBar added to the machine-readable Types list.

[v0.9.8_1] — 2026-07-12 — Graph Rework (experimental)

The experimental Graph relaunched: from a single force simulation to a headless graph model with three deterministic views, relation-type filtering, and semantic navigation. Graph remains experimental — outside the 1.0 semver guarantee. Also ships a categorical Bar fix and the release automation that were waiting under Unreleased.

Added

  • Graph rework — headless model, deterministic views (src/charts/Graph.js, src/graph/). Graph is now a viewport over a headless GraphModel (graphology) that accumulates everything the user walks, fed through a source-adapter contract (neighbors / paths / aggregates; memorySource() simulates a backend over a static payload — swap in a real adapter without touching the class). Three deterministic views replace the force simulation: ego (grid rings by degree of separation, category corners), path (layered "how are A and B connected" routes with endpoint context and the shortest route called out), and cluster (Louvain communities as meta-nodes) — with semantic zoom between ego and cluster, hand-draggable nodes, and identity-preserving recenter transitions. Covered by test/graph.test.js (37 tests: model, layouts, source adapter, and the viewport interaction contract). Documented at /charts/graph/.
  • Graph navigation and filtering (src/charts/Graph.js, rare-charts.css). Relation-type filtering over the ego view — a relationTypes option, setRelationTypes() / clearRelationTypes(), and an interactive legend (click isolates a type, Shift/Ctrl/Cmd-click multi-selects, "Show all" resets); the filter drives both the traversal and what is drawn, and untyped links act as a single default type. Breadcrumb history with back() restores prior ego/path/cluster states together with their filter. The +N more capacity note is now an actionable disclosure listing the capped-out nodes — click one to refocus on it. Removed from the backlog.
  • Graph progressive data contract. Nodes need only an id, links only { source, target }: labels fall back to ids everywhere (canvas, tooltip, breadcrumbs), endpoint nodes are auto-created, link type and weight default sensibly — every view renders from a links-only payload, pinned by contract tests. Removed from the backlog.

Fixed

  • Categorical Bar now renders negative values (src/charts/Bar.js). The vertical and horizontal category modes hard-coded a [0, max] scale domain, so a negative bar computed a negative height/width — an invalid rect that silently didn't render (the time-series mode already handled negatives). The domain now always includes 0 and extends to the data on both sides; bars grow from the zero baseline in both directions, entry animation starts at the baseline, and horizontal value labels flip to the correct side of a negative bar. Covered by test/bar-negatives.test.js.

Changed

  • A GitHub Release is published automatically on release (.github/workflows/sync-charts.yml). The sync already pushed the vX.Y.Z tag (which drives jsDelivr); now it also creates the human-facing card on the rare-charts Releases page, lifting the title and notes from this changelog's entry — so the Releases page no longer lags the tags.

[v0.9.8] — 2026-07-03 — Axes & Accessibility

The pre-freeze groundwork release. Two axes features close out the backlog's Axes section: hiding an axis now reclaims the margin it occupied — so a flush or sparkline look no longer needs a manual margin override — and TimeSeries gains the visibility toggles every other cartesian class already had. Around the code: the library's first automated test suite (122 tests, now gating every deploy and CDN sync), accessibility groundwork (prefers-reduced-motion, accessible names on every chart), a release pipeline where the CDN only ever receives tagged versions, a documentation catch-up for every working option, and an MIT license consistency fix — plus a real adapter bug the new tests caught.

Added

  • Hiding an axis now reclaims its margin (src/charts/Line.js, Bar.js, DualAxes.js, TimeSeries.js). Turning an axis off (showXAxis / showYAxis / showY1Axis / showY2Axis: false) previously only dropped its ticks and labels — the default margin the axis occupied stayed behind, so a flush or sparkline look required a manual margin override. The default margins now track what actually occupies each gutter: a hidden axis collapses its side to 0, and where a gutter is shared the space is kept while any occupant remains — Line/DualAxes keep the right margin while endLabels are on, DualAxes keeps an axis gutter while its y1Title/y2Title is set. An explicit margin always wins. Covered by test/axes-margins.test.js; removed from the backlog.
  • Axis-visibility toggles on RareCharts.TimeSeries (src/charts/TimeSeries.js). The showGrid / showXAxis / showYAxis options that Line, Bar, and DualAxes already expose now work on TimeSeries too — previously its grid and both axes rendered unconditionally. Hidden axes reclaim their margins, same as above. Removed from the backlog.
  • Test harness — Vitest + jsdom (vitest.config.js, test/). First automated tests for the library (122 across 10 files, including the axes tests above). Pure-function coverage of core/utils.js (date parsing, timeframe extents, stroke-dash, marker paths, nice ticks, annotation normalization, motion gating), core/seriesPath.js (line/area/band geometry, baseline), core/theme.js (theme merge), applySvgA11y, and the fromArray adapter — plus render smoke tests that construct every chart type (Line, Bar, Donut, Gauge, DualAxes, TimeSeries, Map via inline GeoJSON, MultiChart with children), feed data, and assert a labelled <svg> renders without throwing, including edge data (empty/all-zero Donut, Gauge value parsing and clamping). jsdom layout/ResizeObserver shimmed in test/setup.js. Run with npm test (watch) or npm run test:run. Tests live in repo-root test/, outside the Eleventy-published assets/charts/.
  • Reduced-motion support (src/core/utils.js → prefersReducedMotion() / motionDuration(), rare-charts.css). Honours the OS prefers-reduced-motion: reduce setting: a CSS media query neutralizes in-chart CSS transitions, and motionDuration() collapses D3 animation durations to 0 so transitions resolve instantly. Applied to every animating chart type — Bar, Line, DualAxes, Donut, Gauge (TimeSeries, Map, MultiChart have no entry animation; Graph is experimental and excluded from 1.0).
  • Accessible name on the chart SVG (src/core/renderHelpers.js → applySvgA11y()). The root <svg> now carries role="img" and an aria-label derived from title/subtitle (or an explicit ariaLabel option), so screen readers announce the chart instead of skipping it. Applied to Bar, Line, TimeSeries, DualAxes, Donut, Gauge, Map (MultiChart delegates to its child charts; Graph is experimental and excluded from 1.0).

Fixed

  • fromArray / data adapters kept rows with a non-finite value (src/adapters/index.js). The filter !row.value || isFinite(row.value) let NaN through because NaN is falsy (!NaN === true), so a row whose value failed to parse (e.g. +'x') was not dropped despite the documented intent. Now uses row.value == null || Number.isFinite(+row.value) — an absent value and a legitimate 0 are kept, a present-but-non-finite value is dropped. Surfaced by the new test suite.

Changed

  • Single source of truth for the version (assets/charts/src/version.json, scripts/build-charts.mjs, _data/versions.js). The version was stamped by hand in four places — index.js, the triplicated build banner across three package.json esbuild scripts, and _data/versions.json — which could (and did, per the old release checklist) drift. Now version.json is the only place to edit: the runtime RareCharts.VERSION, the build banner, and the docs label all read from it. The build moved from inline esbuild CLI calls to a small Node script (scripts/build-charts.mjs) that composes the banner once and emits both bundles; _data/versions.json became _data/versions.js. No change to the public API or bundle output.
  • License field corrected to MIT (package.json). Was ISC, contradicting the LICENSE file and README which both state MIT.
  • Documentation catch-up for existing options (source header comments; docs pages). Every working option is now listed both in its class's header comment — the reference a human or LLM reads next to the code — and in the docs tables. Newly documented: defaultView (all date-based charts), xTicks on Line, animate on MultiChart, reflectY and projection: 'identity' on Map, labelContent and the actual pie-mode defaults on Donut, the global strokeDash/markers group and yAxisPosition on Line, the area/marker group on DualAxes, areaColor and tick formatters on TimeSeries. The Map topoObject doc no longer claims it is required (the code falls back to the topology's first object).
  • Built bundles removed from git (.gitignore). rare-charts.js / rare-charts.min.js are build artifacts: every consumer — the site deploy, the CDN sync, local dev — rebuilds them from src/ via npm run charts:build, so the committed copies could only drift from the source (and had). The source of truth in git is src/; ready-made bundles are distributed from the raredigits/rare-charts repo as before. No change to the published files.
  • Tests gate CI (.github/workflows/deploy.yml, sync-charts.yml). npm run test:run now runs before the site build and before the CDN sync — a failing test blocks both.

[v0.9.7] — 2026-06-19 — Footnotes

Finishes the chart footer. Two new attribution slots — an editorial note and a linkable, multi-part source — so the interpretive line and the data credits live inside the component instead of as hand-built markup glued around it. Plus a set of edge-rendering fixes (axis titles, web-font timing, flush bar labels) that surfaced while wiring a real client chart.

Added

  • source accepts links and multi-part attribution (src/core/Chart.js → _renderAttribution, rare-charts.css). Beyond a plain string, source now takes { text, href } (a single linked attribution) or an array of parts — strings render as plain text, { text, href } objects as links — so a footer can mix several linked and unlinked sources on one line (e.g. Source: NASDAQ, Bloomberg, Internal calculations with the first two linked). Links inherit the source text color (set apart by an underline, so they adapt to light/dark theme), open in a new tab with rel="noopener noreferrer", and an array source wraps instead of truncating so every attribution stays visible. String and HTMLElement sources are unchanged. Flows through MultiChart's shared footer. Removed from the backlog.
  • note text slot on every chart (src/core/Chart.js, rare-charts.css). A new footer option renders a <p class="rc-chart-note"> below the source line in theme.muted, for disclaimers, data caveats, and editorial context. Accepts a string or an HTMLElement. This was the recurring anti-pattern the settings page warned about — interpretive captions hand-built as a stray <div> glued under the chart container — now an in-component slot the chart owns. Long notes wrap (including unbroken tokens like URLs, via overflow-wrap) and the plot shrinks to keep the note inside the card rather than overflowing it. Also flows through MultiChart's shared footer. Documented at /charts/settings/; removed from the backlog.
  • Machine-readable bundle header + RareCharts.VERSION (src/index.js, build banner in package.json). The minified bundle is opaque to anyone — human or LLM — handed only the file. The header now states the global, the new RareCharts.<Type>(selector, options).setData(data) construction pattern, the full list of chart classes, the container requirement, that d3/CSS are bundled, and that external data loads via the fromJson/fromCsv/fromApi/fromArray adapters — so consumers stop guessing class names or hardcoding structure. VERSION is also exported as a runtime constant for build identification. Pairs with the text-slot conventions added to /charts/settings/.

Changed

  • Axis titles clip to their margin instead of running off the chart (src/core/renderHelpers.js → renderAxisTitles, src/charts/DualAxes.js, src/core/utils.js → warnAxisTitleClipped). y1Title / y2Title are now measured by rendered pixel width against the available axis margin (its exact overflow-clip boundary) and trimmed with an ellipsis only when they would actually be cut off — narrow glyphs in a terse title like N · K HLX, and the uppercase transform applied via CSS, are accounted for as they render, so a label that fits (e.g. Inflows) is left intact. The full text is kept as a hover <title>, a one-time console hint fires, and axisTitleMaxLength caps the length explicitly.

Fixed

  • Horizontal bar value-axis end labels no longer clip at the chart edge (src/charts/Bar.js). When the value axis sits flush against the card (margin.left / right = 0), the centered first/last tick label (e.g. 0) was half-cut by the card's overflow clip. The first label is now anchored start and the last end, so both sit fully inside the plot while the bars stay flush.
  • Text-dependent layout now settles after the web font loads (src/core/Chart.js). First paint can happen before the bundled font (Fira Sans) finishes loading, so measurements taken against the wider fallback font were wrong — axis titles that fit were trimmed, X-axis labels over-thinned, end-label boxes mis-sized. Each chart now re-renders once on document.fonts.ready, so these measurements are correct without waiting for a resize. The re-render does not replay entry animations.

[v0.9.6] — 2026-06-14 — Confidence Bands

Adds a band (confidence-ribbon) primitive to Line and the supporting legend and tooltip work to make it readable. Targeted at forecasts and any figure where a single line would overstate precision. Also corrects two strokeDash defects that were documented but didn't work.

Added

  • band series type on RareCharts.Line (src/charts/Line.js, src/core/seriesPath.js). A series marked type: 'band' with { date, lower, upper } points renders a filled ribbon between the two boundaries at each x — for confidence intervals (P10–P90 cones), min/max envelopes, and error bands. The band draws behind every line and area, both bounds participate in the Y scale, and it mixes freely with ordinary line series in the same setData call. Fill uses the series color at fillOpacity (default 0.16). Detected by type: 'band' or by the presence of lower/upper on the first point. Documented at /charts/line/band/ with two examples (examples/line/line-chart-band.js, examples/line/line-chart-forecast.js).
  • Band readout on hover (src/core/Crosshair.js). A band reports its range in the crosshair tooltip as lower – upper (e.g. P10–P90: $1.95M – $3.65M). It draws no crosshair dot — a band has two edges and no single point, so a dot would be ambiguous; markers and end labels skip it for the same reason.
  • Legend swatch types (src/core/Chart.js, rare-charts.css). A legend entry's type now selects its swatch so the legend matches the on-screen encoding: 'band' → filled square, 'dashed' (or dash: true) → dashed rule, 'dot' / 'bar' → dot (unchanged), default → solid rule. Needed because a forecast draws actuals, P50, and the range in a single hue, where the legend has to carry the distinction.

Changed

  • The crosshair only reports a series where its data covers the cursor date (src/core/Crosshair.js). A partial series — a forecast band or a projected line that starts part-way along the axis — no longer snaps its nearest endpoint across the whole width; it stays silent outside its own date range. When nothing is under the cursor, the crosshair line, dots, and tooltip clear. This affects every chart that uses the crosshair, not only bands — in practice it only changes charts whose series span different date ranges.

Fixed

  • Per-series strokeDash was documented but never applied. The field was listed in the Line options table and read during render, but _normalizeData dropped it, so a per-series dash pattern had no effect. It is now carried through and works.
  • resolveStrokeDash rejected raw dash-array strings (src/core/utils.js). The options table implied a value like '4,3' was accepted, but only the named presets ('dashed', 'dotted', 'dashDot', 'longDash') resolved — any raw string fell through to null. A numeric dash-array string (e.g. '5,4', '4 3') is now passed through as-is.
